# CT Wiki Ops

정본은 프로젝트의 `LLM-WIKI.md`, 확인 가능한 원문·코드와 현재 위키다. 코드 정본 구현 문서는 `ct-docs-impl`, 원격 Confluence 입출력은 `ct-wiki-api`의 범위다.

## 호출

- `$ct-wiki-ops`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-wiki-ops <요청>`: 요청과 현재 위키 상태에서 필요한 작업을 판단해 실행한다.
- Claude Code는 `/ct-wiki-ops <요청>`로 호출한다. 호출 뒤 요청이 비어 있으면 안내만 하고 실행하지 않는다.

예: `$ct-wiki-ops 지난 7일의 변경과 남은 작업을 정리해줘`

## 판단

- 기준과 구조가 없으면 `LLM-WIKI.md`와 필요한 기본 구조를 제안한다.
- 원문 보관, 위키 반영, 질문 답변, 기간 요약, 문서 통합, 근거·현재성·구조·링크 점검과 정리 후보 제안을 요청에서 구분한다.
- 정본 우선순위는 사용자 지정, 확인 가능한 원문·코드, 날짜와 근거가 있는 위키, 일반 위키다.
- 충돌은 섞지 않고 선택한 정본, 근거와 시점을 남긴다. 미확인은 사실처럼 쓰지 않는다.

## 변경 안전

- 입력과 출력 파일을 식별하고 요청한 대상만 다룬다.
- 원문은 가공하지 않고 보관하며 같은 대상이 있으면 덮어쓰기 전에 동일성 또는 차이를 확인한다.
- 반영과 통합은 기존 고유 사실, 출처와 링크를 보존한다.
- 정리 후보는 제안만 하며 명시적인 삭제 요청과 복구 경로가 없으면 삭제하지 않는다.

## 완료조건

- 자료를 수집한 뒤 이번 요청의 완료조건을 만든다.
- 개선하고 그 조건으로 검증한다. 고칠 수 있는 미달만 한 번 더 개선한 뒤 다시 검증한다.
- 충족했거나, 남은 미달이 보존·불가이거나, 개선이 2회면 끝낸다.

## 완료 기준

- 변경 작업은 수정 파일, 출처, 충돌 처리와 원본 보존 여부를 보고한다.
- 반영 뒤 근거, 현재성, 필수 메타와 내부 링크를 필요한 범위에서 확인한다.
- 조회와 요약은 답변 근거와 기준 시점을 남긴다.
- 확인하지 못한 내용과 후속 결정이 필요한 항목을 구분한다.
