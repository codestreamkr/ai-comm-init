# CT Wiki Ops

정본은 다음과 같다: 프로젝트의 `LLM-WIKI.md`, 확인할 수 있는 원문과 코드, 현재 위키

다음 작업은 다른 스킬이 담당한다.

- 코드 정본 구현 문서의 작성과 갱신: `ct-apply`
- 원격 Confluence 입출력: `ct-wiki-api`

## 호출

- `$ct-wiki-ops`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-wiki-ops <요청>`: 요청과 현재 위키 상태로 필요한 작업을 판단한다. 그다음 실행한다.
- Claude Code는 `/ct-wiki-ops <요청>`로 호출한다. 요청이 비어 있으면 안내만 한다. 실행하지 않는다.

예: `$ct-wiki-ops 지난 7일의 변경과 남은 작업을 정리해줘`

## 판단

- 기준과 구조가 없으면 `LLM-WIKI.md`와 필요한 기본 구조를 제안한다.
- 요청이 다음 작업 중 어느 것인지 구분한다.
  - 원문 보관
  - 위키 반영
  - 질문 답변
  - 기간 요약
  - 문서 통합
  - 근거·현재성·구조·링크 점검
  - 정리 후보 제안
- 정본 우선순위는 다음 순서다.
  1. 사용자 지정
  2. 확인할 수 있는 원문과 코드
  3. 날짜와 근거가 있는 위키
  4. 일반 위키
- 충돌하는 내용은 섞지 않는다. 선택한 정본, 근거, 시점을 남긴다.
- 미확인 내용은 사실처럼 쓰지 않는다.

## 변경 안전

- 입력 파일과 출력 파일을 식별한다. 요청한 대상만 다룬다.
- 원문은 가공하지 않고 보관한다.
- 같은 대상이 있으면 덮어쓰기 전에 두 파일이 같은지 확인한다. 다르면 차이를 확인한다.
- 반영과 통합에서는 기존 고유 사실, 출처, 링크를 유지한다.
- 정리 후보는 제안만 한다.
- 다음 조건을 모두 충족할 때만 삭제한다: 명시적인 삭제 요청이 있다, 복구 경로가 있다

## 완료조건

- 자료를 수집한 뒤 이번 요청의 완료조건을 만든다.
- 결과를 개선하고 완료조건으로 검증한다.
- 고칠 수 있는 미달 항목이 있으면 한 번 더 개선하고 다시 검증한다.
- 다음 중 하나에 해당하면 끝낸다.
  - 완료조건을 모두 충족했다.
  - 남은 미달 항목이 보존 대상이거나 고칠 수 없다.
  - 개선을 2회 했다.

## 완료 기준

- 변경 작업은 다음 항목을 보고한다: 수정 파일, 출처, 충돌 처리, 원본 보존 여부
- 반영 뒤 다음 항목을 필요한 범위에서 확인한다: 근거, 현재성, 필수 메타, 내부 링크
- 조회와 요약에는 답변 근거와 기준 시점을 남긴다.
- 확인하지 못한 내용과 후속 결정이 필요한 항목을 구분해 보고한다.

완료 후 아래 항목만 짧게 보고한다.

- 수행 작업
- 수정 파일
- 미확인
