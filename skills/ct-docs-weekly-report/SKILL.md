# CT Docs Weekly Report

Git 이력을 근거로 간결한 월별 업무 보고를 쓴다. 사용자가 여러 브랜치를 주면 결과를 합치지 않는다. 브랜치마다 완전한 보고 세트를 따로 만든다.

## 도움말 호출

다음 경우는 도움말 호출이다.

- 스킬 이름 뒤에 요청이 없다.
- 요청이 `?`, `help`, `도움말`, `설명`, `사용법` 중 하나뿐이다.

도움말 호출에는 Git 명령을 실행하지 않는다. 사용 예시만 보여준다. 기능 설명, 입력 항목 설명, 처리 기준은 출력하지 않는다.

다음 실행 예시를 코드 블록으로 출력한다.

```text
$ct-docs-weekly-report를 사용해서 현재 브랜치 보고서를 작성해줘.
```

```text
$ct-docs-weekly-report를 사용해서 2026-08-21~2026-09-20 기간의 아래 브랜치를 각각 작성해줘.

- branch-a
- branch-b
```

```text
$ct-docs-weekly-report로 9월 보고서를 작성해줘.
형식은 .docs/월별보고/8월보고서.md를 참고하고 branch-a와 branch-b를 각각 정리해줘.
```

도움말 호출에는 제목이나 부연 설명을 붙이지 않는다. 저장소 조회, 보고서 생성, 파일 수정을 하지 않는다.

## 입력 결정

- 작성자가 없으면 `P268083`을 사용한다. 이름과 이메일은 대소문자를 구분하지 않는다.
- 브랜치가 없으면 현재 브랜치만 사용한다.
- 브랜치가 하나 이상이면 각 브랜치를 따로 분석한다. 브랜치 사이의 커밋 수나 파일 수를 합치지 않는다.
- 보고 기간이 있으면 그대로 사용한다.
- 보고 기간과 대상 월이 모두 없으면 기준 월은 요청 시점의 달이다. 한국 시간(`Asia/Seoul`)으로 계산한다.
- 대상 월만 주어지면 그 달을 기준 월로 사용한다.
- 기준 월 1일이 포함된 월요일~일요일 구간을 기준 월 1주차로 본다.
- 기본 보고 기간의 시작은 기준 월 1주차 바로 전 월요일 00:00:00이다.
- 기본 보고 기간의 끝은 기준 월 3주차 일요일 23:59:59이다.
- 날짜를 고정하지 않는다. 기준 월의 달력으로 계산한다.
- 기본 보고 기간의 첫 주는 전월 마지막 주로 표기한다. 다음 세 주는 기준 월 1~3주차로 표기한다.
- 기존 보고서가 있으면 그 문서 형식을 따른다. 예: 제목, 대상, 기간, 주차 명칭

## Git 수집

먼저 다음 스크립트를 실행한다. `Since`와 `Until`에는 기간 규칙으로 계산한 값을 넣는다.

```powershell
& "<skill-dir>/scripts/collect_weekly_git.ps1" `
  -Author "P268083" `
  -Since "2026-08-21T00:00:00+09:00" `
  -Until "2026-09-20T23:59:59+09:00" `
  -Branches @("branch-a", "branch-b")
```

스크립트 결과의 각 `branches` 항목이 독립된 보고 세트다.

- merge commit은 제외한다. 부모가 둘 이상인 커밋이 merge commit이다.
- 통합 커밋도 기본으로 제외한다. 통합 커밋은 작성자가 한 명이지만 다른 사람의 변경을 묶을 수 있는 커밋이다. 예: `infi merge`
- 같은 브랜치 안에서는 커밋 해시와 파일 경로를 중복 제거한다.
- 같은 커밋이 다른 브랜치에도 있으면 각 브랜치 결과에 모두 포함한다.
- 브랜치를 체크아웃하거나 작업 트리를 변경하지 않는다.

커밋 제목만으로 의미가 불명확하면 `git show --stat <hash>`를 확인한다. 관련 파일의 diff도 필요한 범위만 확인한다. 실제 변경에서 확인하지 못한 업무는 추정하지 않는다.

## 주차별 업무 작성

- 기존 보고서의 주차 구분을 먼저 따른다. 별도 기준이 없으면 월요일부터 일요일까지를 한 주로 본다.
- 같은 기능에 속하는 연속 커밋은 하나의 업무로 합친다.
- 큰 커밋 하나에 서로 다른 기능이 있으면 확인한 기능 단위로 나눌 수 있다.
- 주차별 목표는 3~4건이다. 근거가 부족하면 개수를 억지로 채우지 않는다.
- 병합, 포맷 정리, 단순 파일 이동은 독립 업무로 쓰지 않는다.
- 업무명은 구현 결과 중심의 명사형으로 간결하게 쓴다.

예시:

```markdown
### 9월 2주차

- 결제 프로모션 DB 구조 변경과 응답 항목 확장
- 클라이언트별 PG 키 조회·검증 및 승인 구조 적용
- 주요 간편결제 분기와 주문·클레임 화면 처리 개선
```

## 대표 파일 산정

각 브랜치에서 보고 대상 커밋이 변경한 파일로 계산한다. 중복 파일은 제거한다.

- Java: `src/main/java` 아래의 `.java`만 집계한다. `src/test/java`는 기본 수치에서 제외한다.
- JSP: 경로와 관계없이 `.jsp`를 집계한다.
- 대표 파일은 해당 브랜치의 대상 커밋에서 가장 자주 변경된 파일이다.
- 빈도가 같으면 보고서의 주요 작업을 가장 잘 나타내는 파일을 고른다.
- 표기 형식은 `외 N개`이다. N은 전체 고유 파일 수에서 대표 파일 하나를 뺀 값이다.
- 해당 유형의 파일이 없으면 `해당 없음`으로 쓴다.

```markdown
### Java

OrderMngApiController.java 외 35개

### JSP

ecoupon_order_mng_after.jsp 외 25개
```

테스트 파일 수는 사용자가 요청할 때만 따로 표시한다.

## 출력 구조

브랜치가 하나면 기존 보고서 구조를 유지한다. 브랜치가 여러 개면 아래 구조를 브랜치별로 반복한다.

```markdown
## branch-a

### 주차별 업무

#### 9월 1주차

- 작업 내용

### 대표 파일

#### Java

Representative.java 외 N개

#### JSP

representative.jsp 외 N개
```

## 파일 생성

보고서는 항상 Markdown 파일로 저장한다. 사용자가 파일 생성을 요청하지 않아도 저장한다.

- 사용자가 출력 경로를 지정하면 그 경로를 사용한다.
- 사용자가 기존 보고서를 형식 기준으로 주고 출력 경로를 지정하지 않으면 그 파일을 갱신한다.
- 그 밖의 경우에는 저장소 루트의 `.docs/월별보고/YYYY-MM-업무보고.md`에 만든다. `YYYY-MM`은 보고 기간 종료일의 연월이다.
- 상위 폴더가 없으면 만든다.
- 같은 출력 파일이 있으면 해당 보고 기간과 브랜치의 내용만 새 수집 결과로 갱신한다. 관련 없는 기존 내용은 유지한다.
- 저장한 뒤 파일을 다시 읽는다. 제목, 기간, 브랜치, 주차별 업무, 대표 파일이 모두 있는지 확인한다.

## 결과 보고

사용자에게 다음 내용만 짧게 보고한다. 보고서 전문은 반복하지 않는다.

- 만들거나 수정한 파일 경로
- 적용한 작성자, 기간, 브랜치
- 반영 커밋 수와 제외한 통합 커밋 수
- 검증하지 못한 항목이 있으면 그 사유
