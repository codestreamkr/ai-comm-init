# LLM Wiki 작업 규칙

이 문서는 LLM Wiki를 운영할 때 따르는 실행 규칙이다.

## 기본 원칙

위키는 원문을 근거로 누적 관리한다.

- 원문 자료는 `.wiki/raw/`에 둔다.
- LLM은 `.wiki/raw/` 안의 원문을 수정하지 않는다.
- LLM이 작성하고 수정하는 문서는 `.wiki/raw/`를 제외한 `.wiki/` 하위에 둔다.
- 모든 주요 주장에는 가능한 한 출처 문서를 연결한다.
- 새 자료가 기존 내용과 충돌하면 기존 문서를 조용히 덮어쓰지 않고 충돌 내용을 기록한다.
- 질문 답변 중 재사용 가치가 있는 내용은 `.wiki/questions/` 또는 `.wiki/synthesis/`에 문서로 남긴다.
- LLM Wiki 운영 안내는 이 문서에 둔다.

## 디렉터리

위키는 아래 구조만 사용한다.

- `.wiki/raw/`: 원문 자료
- `.wiki/raw/assets/`: 원문에 딸린 이미지, PDF, 첨부 파일
- `.wiki/index.md`: 전체 색인
- `.wiki/log.md`: 작업 이력
- `.wiki/sources/`: 원문별 요약 문서
- `.wiki/concepts/`: 개념 문서
- `.wiki/entities/`: 사람, 조직, 제품, 장소 문서
- `.wiki/questions/`: 질문과 답변에서 나온 분석 문서
- `.wiki/synthesis/`: 여러 자료를 종합한 주제 문서
- `.wiki/templates/`: 문서 템플릿

## 문서 작성 기준

문서는 빠르게 읽고 갱신할 수 있게 쓴다.

- 제목은 문서의 대상을 바로 드러낸다.
- 첫 문장은 문서의 목적이나 결론을 짧게 쓴다.
- 핵심 내용은 항목명으로 나눈다.
- 원문 표현보다 한국어 실무 문장으로 정리한다.
- 코드명, API명, 제품명, 외부 서비스명은 원문 표기를 유지한다.
- 불확실한 내용은 단정하지 않고 `확인 필요`로 표시한다.
- 같은 개념을 새 이름으로 중복 생성하지 않고 기존 문서를 먼저 찾는다.
- 문서 하단에는 `## 이력관리`를 둔다.

## 출처 표기

출처는 추적 가능해야 한다.

- 원문 파일이 있으면 `.wiki/raw/` 경로를 적는다.
- 웹 출처는 URL과 확인일을 적는다.
- 하나의 문서가 여러 출처를 종합하면 `## 출처`에 모두 적는다.
- 출처 없는 추론은 `## 해석` 또는 `## 확인 필요`에 분리한다.

## Ingest 절차

새 원문은 하나씩 처리한다.

- 1단계: `.wiki/raw/`에서 새 원문을 확인한다.
- 2단계: 기존 `.wiki/index.md`를 읽고 관련 문서를 찾는다.
- 3단계: `.wiki/sources/`에 원문 요약 문서를 만든다.
- 4단계: 관련 `concepts`, `entities`, `synthesis` 문서를 갱신한다.
- 5단계: 새 링크와 한 줄 요약을 `.wiki/index.md`에 반영한다.
- 6단계: 처리 결과를 `.wiki/log.md`에 추가한다.

## Query 절차

질문은 위키를 먼저 기준으로 답한다.

- 1단계: `.wiki/index.md`에서 관련 문서를 찾는다.
- 2단계: 관련 문서를 읽고 답변한다.
- 3단계: 답변에 사용한 근거 문서를 표시한다.
- 4단계: 재사용 가치가 있으면 새 문서로 저장할지 사용자에게 확인한다.

## Lint 절차

위키 상태는 주기적으로 점검한다.

- 모순된 주장
- 오래된 주장
- 출처 없는 핵심 주장
- 링크가 없는 고립 문서
- 문서가 필요한데 없는 개념
- 중복 개념 문서
- 색인 누락 문서
