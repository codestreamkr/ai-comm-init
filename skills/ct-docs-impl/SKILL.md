# CT 구현 문서

검증된 사실 중 구현·조회·검증에 필요한 결과만 남긴다.
조사 과정은 문서에 쓰지 않는다.

## 단독 호출

사용자가 이 스킬만 호출했거나 작업 정보가 부족하면 파일을 변경하지 말고 안내한다.

> 구현 문서를 새로 작성하거나, 여러 자료를 통합하거나, 기존 문서를 정리할 수 있습니다.
>
> 다음 정보를 알려주세요.
>
> - 작업 유형: 신규 작성 / 변경 적용 / 자료 통합 / 기존 문서 정리 / 현재 구현으로 갱신
> - 대상 범위
> - 참고할 문서·코드·설정 또는 디렉터리
> - 결과 파일 경로
> - 강조할 항목이 있다면 해당 항목

이미 대화나 작업공간에서 확인할 수 있으면 다시 묻지 않는다.
결과를 크게 바꾸는 정보만 질문한다.

## 문서 종류

종류를 먼저 고른다. 한 문서에 섞지 않는다.

| 종류 | 쓰는 내용 | 저장 |
|---|---|---|
| 현재 구현 | 지금 코드가 하는 일 | 기존 구현 문서 |
| 변경 적용 | 아직 코드에 없는 적용 기준 | 신규 문서 |
| 반영 후 갱신 | 코드에 들어간 뒤의 현재 구현 | 기존 구현 문서 |

바로 개발하라는 요청이어도 미반영 변경은 신규 문서다.
기존 구현 문서는 코드가 바뀐 뒤에만 결과에 맞게 갱신한다.
코드 반영 전에 기존 문서를 목표 상태로 고치지 않는다.

요청 범위를 넘어 다른 문서를 일괄 정리하지 않는다.
기존 문서를 수정할 때는 기술적 의미와 사용자 고유 표현을 보존한다.

## 화이트리스트

확인된 사실이어도 아래만 남긴다.

남긴다.

- 범위: 한다 / 하지 않는다
- 진입점, 파일, 식별자
- 필드·컬럼 대응
- 조회·매핑·정렬 조건
- 예외·제한으로 동작이 갈리는 규칙
- 검증 기준과 실행 명령
- 코드와 자료가 다를 때, 선택한 정본 한 줄

남기지 않는다.

- 조사·검토·대안 비교 과정
- 대화에서 바뀐 해석의 이력
- 개발에 필요 없는 배경 반복
- 같은 사실의 개요/상세 이중 서술
- 빈 섹션, 형식 맞추기용 목차

## 작업

1. 문서 종류와 저장 위치를 정한다.
2. 관련 코드·자료만 확인하고 정본을 고른다.
3. 화이트리스트에 걸린 사실만 병합한다.
4. 개요식 본문으로 쓰고 식별자를 검증한다.

프로젝트 정본 기준이 있으면 따른다. 없으면 다음 순서로 고른다.

1. 사용자가 지정한 정본
2. 실제 코드와 설정
3. 구체적이고 최신인 자료
4. 일반 자료 또는 이전 자료

충돌은 섞지 않는다. 의미 있는 차이는 정본 한 줄로 남긴다.
자료 간 연결이 확인되지 않으면 추론해 추가하지 않는다.

코드에서 직접 확인한다.

- 소스 구조와 파일 경로
- 클래스·메서드·필드 이름
- 진입점과 엔드포인트
- 위치 표기
- 설정 키와 기본값

자료와 코드가 다르면 코드를 적고, 무엇이 달랐는지는 보고에만 남긴다.

변경 가능성이 있는 상세 규칙과 값은 한 문서만 정본으로 둔다.
다른 문서는 요약과 참조만 한다. 참조는 문서명과 그 문서가 정하는 내용을 한 줄로 적는다.

자료를 통합한 뒤 원본을 정리할 때:

- 원본에만 있고 결과 문서에도 코드에도 없는 사실이 남았는지 대조한다.
- 원본을 가리키는 링크를 먼저 갱신한다.
- 복구 경로가 없으면 삭제하지 않고 사용자에게 알린다.

## 산출물

제목 아래 한 문장으로 이 문서가 정하는 결과를 적는다.
정본, 다루지 않는 범위, 공통 규칙 문서는 필요할 때만 밝힌다.

섹션은 후보다. 화이트리스트에 걸린 내용이 있는 것만 쓴다.
저장소 관례가 있으면 따른다.

- 범위
- 개요
- 소스 구조
- 처리 흐름
- 규칙
- 제한
- 검증
- 관련 문서

처리 흐름이 여러 개면 단계 표로 업무가 먼저 보이게 쓴다.
호출 경로는 본문을 방해할 때만 접는다.
위치는 `파일:라인` 또는 `:라인`이다. 라인 번호는 정본이 아니다.

표현은 표와 목록을 우선한다.
문단은 규칙이 표에 안 들어갈 때만 쓴다.
코드 예시는 복사해 쓸 조각만 둔다.
표가 넓으면 열을 나누거나 목록으로 내린다. 셀 안에 `<br>`을 쓰지 않는다.

## 문체와 줄바꿈

- 결론을 먼저 쓴다. 한 항목에 결론 하나다.
- “왜”는 동작이 달라질 때만 적는다.
- 코드, 식별자, 명령어, 로그, 경로는 원문을 유지한다.
- 짧은 문장과 명사형 표제를 쓰되 의미가 끊기지 않게 한다.

줄바꿈은 의미 단위다. 칸 수를 맞추지 않는다.

- 한 줄에 사실 하나
- 조건과 결과는 줄을 나눈다
- 나열은 목록이나 표로 내린다
- 식별자·경로·SQL은 나누지 않는다
- 칸을 채우려고 이어 쓰지 않는다

## 검증

- 경로와 식별자가 자료 또는 코드에 있는지 확인한다.
- 링크, 코드 펜스, 표, `<details>`가 올바른지 확인한다.
- 한 줄에 사실이 둘 이상인지, 식별자가 쪼개졌는지 확인한다.
- 자동 검증을 실행하지 않은 구간은 실행한 것처럼 쓰지 않는다.
- 문서와 구현의 차이는 적용한 정본과 함께 보고한다.
- 정본으로 확인할 수 없어 제외한 항목은 목록으로 보고한다.
  그 자료가 유일한 기록이면 보존 여부를 확인받는다.

## 필수 제한

- 확인되지 않은 사실을 만들지 않는다.
- 보기 좋게 만들기 위해 기술적 의미나 예외를 숨기지 않는다.
- 비밀값이나 마스킹되지 않은 개인정보를 기록하지 않는다.
