# CT Docs Impl

정본은 코드와 설정이다. 산출은 구현·조회·검증에 필요한 결과만 담은 Markdown이며 조사 과정은 쓰지 않는다.

## 호출

- `$ct-docs-impl`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-docs-impl <요청>`: 요청과 대상 상태에서 필요한 문서 작업을 판단해 실행한다.
- Claude Code는 `/ct-docs-impl <요청>`로 호출한다. 호출 뒤 요청이 비어 있으면 안내만 하고 실행하지 않는다.

예: `$ct-docs-impl payment.md를 현재 코드에 맞춰줘`

## 판단

- 지금 코드의 문서가 없으면 새로 작성한다.
- 아직 코드에 없는 변경 기준은 기존 구현 문서를 목표 상태로 고치지 않고 별도 신규 문서에 둔다.
- 기존 문서 정리, 여러 자료의 통합, 코드 반영 후 동기화는 요청과 파일 상태에서 판단한다.
- 저장 경로는 사용자 지정 또는 프로젝트 관례를 따르고 둘 다 없으면 확인한다.
- 위키 지식의 통합은 `ct-wiki-ops`의 범위로 남긴다.

## 내용 기준

정본 순서는 사용자 지정, 실제 코드와 설정, 구체적이고 최신인 자료, 일반·이전 자료다. 자료와 코드가 다르면 현재 구현은 코드를 따르고 차이를 보고한다. 미반영 변경은 현재 사실과 섞지 않는다.

아래를 기본으로, 구현·운영·검증 판단에 직접 필요한 확인 사실만 추가한다.

- 범위와 제외 범위
- 진입점, 파일과 식별자
- 필드·컬럼 대응과 상태 변화
- 조회·매핑·정렬·트랜잭션·권한 조건
- 외부 계약과 예외·제한으로 동작이 갈리는 규칙
- 검증 기준과 실행 명령

조사 과정, 대안 비교, 불필요한 배경, 같은 사실의 반복과 빈 섹션은 남기지 않는다. 식별자·경로·명령과 사용자 고유 표현은 보존한다.

## 완료 기준

- 경로와 식별자가 코드나 자료에 존재하는지 확인한다.
- 변경 가능성이 있는 규칙과 값은 한 문서만 정본으로 두고 다른 문서는 참조한다.
- 통합하거나 대체한 문서의 고유 사실과 링크를 대조하며 복구 경로 없이 원본을 삭제하지 않는다.
- 변경 파일, 대상 밖 변경 없음, 링크·경로 확인 결과와 실행하지 못한 검증을 보고한다.
- 비밀값과 마스킹되지 않은 개인정보를 기록하지 않는다.
