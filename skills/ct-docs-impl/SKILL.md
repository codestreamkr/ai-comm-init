# CT Docs Impl

정본은 코드와 설정이다. 산출은 구현·조회·검증에 필요한 결과만 있는 Markdown이다. 조사 과정은 쓰지 않는다.

## 호출

- `$ct-docs-impl` 또는 `$ct-docs-impl ?`: 안내. 실행하지 않는다.
- `$ct-docs-impl <작업> ?`: 해당 작업 안내.
- `$ct-docs-impl <작업> <대상>`: 실행.

첫 토큰이 `new`, `change`, `merge`, `tidy`, `sync`가 아니면 안내만 한다. `--`로 시작하면 지원하지 않는 옵션이다. 작업 다음 대상이 없으면 안내한다. 저장 경로는 사용자 지정 또는 프로젝트 관례로 정하고, 없으면 묻는다. 이미 확인된 정보는 다시 묻지 않는다.

## 작업

- `new`: 지금 코드의 `현재 구현` 문서를 새로 쓴다. 미반영 변경은 `change`다.
  - 예: `$ct-docs-impl new OrderService.cancel`
- `change`: 아직 코드에 없는 적용 기준. 종류는 `변경 적용`, 저장은 신규 파일. 기존 구현 문서를 목표 상태로 고치지 않는다.
  - 예: `$ct-docs-impl change 쿠폰 중복 적용 방지`
- `merge`: 여러 자료를 한 구현 문서로 합친다. 위키 종합은 `ct-wiki-ops merge`다.
  - 예: `$ct-docs-impl merge .docs/order-*.md`
- `tidy`: 기존 구현 문서를 정리한다. 기술적 의미와 사용자 고유 표현은 유지한다. 요청 밖 문서를 일괄 정리하지 않는다.
  - 예: `$ct-docs-impl tidy .docs/order-cancel.md`
- `sync`: 코드가 바뀐 뒤 기존 문서를 `현재 구현`으로 맞춘다. 코드 반영 전에는 쓰지 않는다.
  - 예: `$ct-docs-impl sync .docs/order-cancel.md`

## 역할 규칙

종류를 섞지 않는다.

| 종류 | 내용 | 저장 |
|---|---|---|
| 현재 구현 | 지금 코드가 하는 일 | 기존 구현 문서 |
| 변경 적용 | 아직 코드에 없는 적용 기준 | 신규 문서 |
| 반영 후 갱신 | 코드에 들어간 뒤의 현재 구현 | 기존 구현 문서 |

정본 순서: 사용자 지정, 실제 코드와 설정, 구체적이고 최신인 자료, 그다음 일반·이전 자료. 충돌은 섞지 않고 정본 한 줄로 남긴다. 자료와 코드가 다르면 코드를 쓰고 차이는 보고에만 둔다. 연결이 확인되지 않은 사실을 추론해 넣지 않는다.

변경 가능성이 있는 상세 규칙과 값은 한 문서만 정본으로 둔다. 다른 문서는 요약과 참조만 한다.

확인된 사실이어도 아래만 남긴다.

- 범위: 한다 / 하지 않는다
- 진입점, 파일, 식별자
- 필드·컬럼 대응
- 조회·매핑·정렬 조건
- 예외·제한으로 동작이 갈리는 규칙
- 검증 기준과 실행 명령
- 코드와 자료가 다를 때 선택한 정본 한 줄

남기지 않는다: 조사·대안 비교, 해석 이력, 개발에 필요 없는 배경, 같은 사실의 개요/상세 이중 서술, 빈 섹션.

식별자·경로·명령은 원문 그대로다. 섹션과 문체는 프로젝트 관례를 따른다. 화이트리스트에 없는 칸을 채우지 않는다.

`merge` 후 원본을 정리할 때, 결과와 코드에 없는 원본 고유 사실이 남았는지 대조한다. 링크를 먼저 고친다. 복구 경로가 없으면 삭제하지 않는다.

경로와 식별자는 자료 또는 코드에 있는지 확인한다. 실행하지 않은 검증을 실행한 것처럼 쓰지 않는다. 비밀값과 마스킹되지 않은 개인정보를 기록하지 않는다.
