# CT Apply

정본은 확정된 요구사항·계획과 현재 프로젝트의 코드·설정·테스트다. 요청한 변경을 끝까지 구현한다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력과 예제만 안내한다.
- 계획이 있으면 먼저 계획과 현재 코드를 읽어 완료·미완료·막힌 작업을 확인한다. 계획이 없는 직접 수정 요청은 요청 범위와 확인 가능한 완료 조건을 정해 진행한다.

예: `$ct-apply 주문 취소 구현 계획의 남은 작업을 완료해줘`

## 수행

- 남은 작업을 순서대로 구현하고 각 항목에 필요한 테스트·빌드·정적 검사 또는 실행 확인을 수행한다. 검증 근거가 생긴 뒤에만 완료로 표시한다.
- 프로젝트의 언어·프레임워크·의존성 버전과 같은 역할의 코드 관례를 먼저 확인한다. 관련 호출부, 설정, 데이터·예외 계약을 함께 맞춘다.
- 테스트는 주요 정상·실패·경계 동작을 검증하고 단순 구현 세부사항을 고정하지 않는다. 쿼리 변경은 가능한 같은 조건에서 전후 결과의 동일성과 성능을 확인한다.
- 계획 파일이 있으면 그 파일에 항목별 완료 상태를 갱신한다. 없으면 작업 상태와 검증 결과를 최종 보고에 남긴다.
- 구현 중 요구사항·범위·완료 기준이 바뀌거나 결과를 바꾸는 해석이 둘 이상이면 해당 항목을 멈추고 확인받는다. 독립적인 나머지 작업은 계속한다.

## 완료

- 모든 확정 작업이 검증되어 완료될 때까지 반복한다. 개선 횟수나 한 번의 테스트 성공을 종료 기준으로 삼지 않는다.
- 구체적인 장애로 더 진행할 수 없으면 완료·미완료·막힌 항목, 검증 결과, 필요한 입력과 재개 지점을 구분해 보고한다.
- 종료 전 계획의 모든 요구사항과 실제 변경·검증 결과를 대조한다. 수행하지 못한 검증은 완료로 표시하지 않는다.

## 결과 보고

- 완료·미완료·막힌 작업, 변경 파일, 항목별 검증 결과와 못 한 검증을 짧게 보고한다.
- 전체 요구사항을 검증할 수 있도록 `ct-verify`에 넘길 계획·변경 결과와 남은 위험을 명시한다.
