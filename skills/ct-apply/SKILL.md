# CT Apply

확정된 계획을 현재 프로젝트의 환경과 관례에 맞게 끝까지 실행한다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력과 예제만 안내한다.
- 지정된 계획과 현재 상태를 읽어 완료·미완료·막힌 작업을 확인한다. 계획이 지정되지 않았고 대화나 프로젝트에서 하나로 특정할 수 없으면 대상 계획을 확인받는다.
- 각 요구사항의 완료 조건과 검증 방법을 확인한다. 계획이 없거나 기준이 빠졌으면 해당 작업의 구현 전에 확인받는다. 결과를 바꾸는 미결정 사항도 확인받는다.

예: `$ct-apply 주문 취소 구현 계획의 남은 작업을 완료해줘`

## 수행

- 프로젝트의 언어·의존성·빌드·실행·테스트 수단과 기존 관례를 확인한다.
- 확정 계획의 작업 순서·수정 영역·대상 파일·완료 조건·검증 방법을 실행 기준으로 사용한다. 시작 시 현재 변경 상태와 대조해 남은 작업을 수정 영역별로 짧게 보고한다.
- 계획의 수정 영역별로 실행·검증하고, 진행 중에는 완료한 영역·검증 결과·다음 작업을 보고한다. 검증된 항목만 완료로 표시한다.
- 실제 대상 파일이나 변경 범위가 계획과 달라지면 변경 내용과 이유를 보고하고 계획을 갱신한다. 결과를 바꾸는 미결정 사항은 확인받은 뒤 진행한다.
- 계획 파일이 있으면 실행 상태와 검증 결과를 기록한다. 대화에서 확정한 계획도 같은 작업 순서와 수정 영역을 유지해 보고한다.
- 요구사항·범위·완료 조건이 달라지거나 해석이 갈리면 해당 항목을 멈추고 계획 갱신 또는 결정을 요청한다. 독립 작업은 계속한다.

## 완료

- 모든 확정 작업이 검증되어 완료되거나 구체적인 장애로 더 진행할 수 없을 때 종료한다. 임의의 횟수 제한으로 끝내지 않는다.
- 종료 전 계획의 모든 요구사항과 실제 결과를 대조한다. 못 한 검증은 완료로 표시하지 않는다.
- 종료 보고는 확정 계획과 같은 작업 순서·수정 영역으로 정리하고, 각 영역의 변경 파일·변경 결과·검증 결과·남은 사항을 함께 표시한다.
- 같은 목적의 여러 파일은 한 묶음으로 나열하고 설명은 한 번만 작성한다.
- 전체 완료 여부, 계획 대비 변경점, 미완료·막힌 작업과 재개 지점을 짧게 보고한다. `ct-verify`가 확인할 항목과 미검증 사항을 명시한다.
