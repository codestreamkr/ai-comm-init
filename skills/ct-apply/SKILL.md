# CT Apply

다음 작업을 현재 프로젝트의 환경과 관례에 맞게 끝까지 실행한다.

- 확정된 계획
- `ct-verify`가 전달한 실패 수정 작업

## 호출

- 요청 없이 호출하면 역할, 필요한 입력, 예제만 안내한다.
- 지정된 계획과 현재 상태를 읽는다. 완료, 미완료, 막힌 작업을 확인한다.
- `ct-verify`가 실패 수정을 요청하면 실패 항목을 다시 처리한다. 이전 완료 표시는 무시한다.
- `ct-verify`가 전달한 다음 기준이 확정되어 있으면 그 기준을 실행 계획으로 사용한다. 별도 계획 파일을 요구하지 않는다.
  - 요구사항
  - 기대 결과
  - 수정 범위
  - 검증 방법
- 그 밖의 경우에 다음 조건을 모두 충족하면 대상 계획을 사용자에게 확인한다.
  - 사용자가 계획을 지정하지 않았다.
  - 대화나 프로젝트에서 계획을 하나로 특정할 수 없다.
- 각 요구사항의 완료 조건과 검증 방법을 확인한다.
- 다음 경우에는 해당 작업을 구현하기 전에 사용자에게 확인한다.
  - 계획이나 확정된 실패 수정 기준이 없다.
  - 필요한 기준이 빠졌다.
  - 결과를 바꾸는 미결정 사항이 있다.

예: `$ct-apply 주문 취소 구현 계획의 남은 작업을 완료해줘`

## 수행

- 프로젝트의 다음 항목과 기존 관례를 확인한다: 언어, 의존성, 빌드, 실행, 테스트 수단
- 확정 계획의 다음 항목을 실행 기준으로 사용한다: 작업 순서, 수정 영역, 대상 파일, 완료 조건, 검증 방법
- 시작할 때 계획과 현재 변경 상태를 비교한다. 남은 작업을 수정 영역별로 짧게 보고한다.
- 계획의 수정 영역 단위로 실행하고 검증한다.
- 진행 중에는 완료한 영역, 검증 결과, 다음 작업을 보고한다.
- 검증한 항목만 완료로 표시한다.
- 실제 대상 파일이나 변경 범위가 계획과 다르면 변경 내용과 이유를 보고한다. 그다음 계획을 갱신한다.
- 결과를 바꾸는 미결정 사항은 사용자에게 확인한 뒤 진행한다.
- 계획 파일이 있으면 실행 상태와 검증 결과를 기록한다.
- 대화에서 확정한 계획도 같은 작업 순서와 수정 영역으로 보고한다.
- 요구사항, 범위, 완료 조건이 바뀌거나 해석이 둘 이상이면 해당 항목을 멈춘다. 계획 갱신이나 결정을 요청한다.
- 독립 작업은 계속 진행한다.

## 완료

- 다음 중 하나에 해당하면 종료한다. 임의의 횟수 제한으로 끝내지 않는다.
  - 모든 확정 작업을 검증하고 완료했다.
  - 구체적인 장애로 더 진행할 수 없다.
- 종료 전에 계획의 모든 요구사항과 실제 결과를 비교한다.
- 하지 못한 검증은 완료로 표시하지 않는다.
- 종료 보고는 확정 계획과 같은 작업 순서와 수정 영역으로 정리한다.
- 각 영역에 다음 항목을 함께 표시한다: 변경 파일, 변경 결과, 검증 결과, 남은 사항
- 같은 목적의 여러 파일은 한 묶음으로 나열한다. 설명은 한 번만 쓴다.
- 다음 항목을 짧게 보고한다: 전체 완료 여부, 계획 대비 변경점, 미완료 작업, 막힌 작업, 재개 지점
- `ct-verify`가 확인할 항목과 미검증 사항을 명시한다.
- `ct-verify`의 실패 수정 요청으로 실행했으면 다음 항목을 반환한다: 변경 내용, 검증 명령과 결과, 남은 실패, 장애
- 이 경우 `ct-verify`를 다시 호출하지 않는다. 재검증과 다음 수정 요청은 호출한 `ct-verify`가 관리한다.
