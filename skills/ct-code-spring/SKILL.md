# CT Code Spring

정본은 프로젝트의 빌드 설정, Spring 설정과 같은 역할의 기존 코드다. 일반 Spring 관례보다 확인된 프로젝트 패턴을 앞세운다.

## 호출

- `$ct-code-spring`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-code-spring <요청>`: 요청에서 검토인지 변경인지 판단해 실행한다.
- Claude Code는 `/ct-code-spring <요청>`로 호출한다. 호출 뒤 요청이 비어 있으면 안내만 하고 실행하지 않는다.

예: `$ct-code-spring 주문 취소 트랜잭션을 구현해줘`

## 판단

- 검토 요청은 읽기 전용으로 수행하고 코드를 수정하지 않는다.
- 구현, 수정, 추가 요청은 관련 코드와 설정을 필요한 범위에서 변경한다. 공통 컴포넌트도 별도 작업으로 구분하지 않는다.
- 구현 계획만 필요하면 `ct-plan-work`, 사용자 흐름 검증만 필요하면 `ct-qa-flow`의 범위로 남긴다.
- 변경 여부가 불명확하고 결과가 달라지면 먼저 확인한다.

## 완료 기준

- Spring과 의존성 버전은 `pom.xml`, Gradle 파일, wrapper, lockfile과 실제 설정 중 프로젝트에 있는 근거로 확인한다.
- 관련 설정, 호출부, 데이터·예외 계약과 기존 테스트를 확인하고 요청 밖 구조를 바꾸지 않는다.
- 프로젝트에 없는 API나 패턴을 가정하지 않는다. 프로젝트 근거로 확정할 수 없을 때만 해당 버전의 공식 문서를 확인한다.
- 변경에는 영향에 맞는 기존 빌드, 테스트 또는 정적 검사를 선택해 실행한다.
- 검토·변경 근거, 영향 범위, 검증 결과와 실행하지 못한 검증 사유를 보고한다.
