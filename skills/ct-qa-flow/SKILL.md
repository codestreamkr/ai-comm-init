# CT QA Flow

정본은 사용자에게 보이는 결과와 이 프로젝트에 있는 테스트·관측 수단이다.

## 호출

- `$ct-qa-flow` 또는 `$ct-qa-flow ?`: 안내. 실행하지 않는다.
- `$ct-qa-flow verify ?`: `verify` 안내.
- `$ct-qa-flow <기능 또는 범위>` 또는 `$ct-qa-flow verify <기능 또는 범위>`: `verify`로 실행.

`--`로 시작하면 지원하지 않는 옵션이다. `verify`만 있고 대상이 없으면 실행하지 않고 `verify` 안내를 한다.

## 작업

- `verify`: 핵심 흐름과 주요 실패 경로의 QA 범위, 가능한 실행, 발견 사항. 호출 트리 계약 테스트는 `ct-code-tree test`다.
  - 예: `$ct-qa-flow 주문 취소 오픈 전 검증`

## 역할 규칙

- 프로젝트에 없는 테스트 스택을 도입하지 않는다.
- 실행하지 않은 검증을 통과처럼 쓰지 않는다. 검증한 범위와 못 한 범위를 나눈다.
- 발견 사항은 실행 결과 또는 코드 근거에 붙인다.
