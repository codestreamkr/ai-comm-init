# CT QA Flow

정본은 사용자에게 보여야 하는 결과, 현재 코드와 프로젝트에 있는 테스트·관측 수단이다.

## 호출

- `$ct-qa-flow`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-qa-flow <요청>`: 대상 기능의 위험을 정하고 가능한 검증을 수행한다.

예: `$ct-qa-flow 주문 취소 기능을 오픈 전에 검증해줘`

## 판단

- 사용자 성공 기준, 진입점, 환경, 권한과 필요한 데이터를 확인한다.
- 필요한 입력을 확보하지 못하면 추정하지 않고 실행 가능한 범위만 설계하며, 검증 불가 사유와 필요한 다음 입력을 남긴다.
- 정상 흐름을 기준으로 결과를 바꾸는 실패·경계 조건을 위험 순서로 선택한다.
- 프로젝트에 있는 테스트와 관측 수단을 우선하고 새 테스트 스택을 도입하지 않는다.
- 호출 흐름에 근거한 테스트 코드 작성은 `ct-code-tree-test`의 범위로 남긴다.

## 완료 기준

- 실행한 각 위험을 사전조건, 실행 절차, 관측 결과와 통과·실패 판정에 연결한다.
- 실행 결과 또는 코드 근거가 있는 발견만 확정한다.
- 발견한 결함에는 재현 조건과 영향 범위를 남긴다.
- 검증한 범위, 결과, 재현 방법과 환경 제약으로 검증하지 못한 범위를 구분해 보고한다.
