# CT Plan Work

정본은 프로젝트와 사용자가 준 자료다. 산출은 요청한 계획 또는 검토 결과이며 운영 코드는 바꾸지 않는다.

## 호출

- `$ct-plan-work`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-plan-work <요청>`: 요청에서 필요한 결과와 대상을 판단해 실행한다.
- Claude Code는 `/ct-plan-work <요청>`로 호출한다. 호출 뒤 요청이 비어 있으면 안내만 하고 실행하지 않는다.

예: `$ct-plan-work 주문 취소 기능의 구현 계획을 작성해줘`

## 판단

요청의 목적을 아래 결과 중 하나로 좁힌다. 표현이 달라도 목적이 명확하면 바로 진행하고, 결과가 달라지는 모호함만 확인한다.

- 제품 기획: 목표, 사용자, 흐름, 요구사항과 성공 기준
- 설계 검토: 기존 설계의 근거, 영향, 위험, 대안과 결정 항목
- 구현 계획: 변경 범위, 영향, 순서와 검증 기준
- 구조 전환 계획: 현재·목표 구조, 단계별 전환, 호환·중단·복구 조건
- 개선 계획: 현황 근거, 개선 과제, 우선순위와 기대 효과

한 요청에 여러 결과가 필요하면 의존 순서로 연결하되 요청 밖 산출을 만들지 않는다.

## 완료조건

- 자료를 수집한 뒤 이번 요청의 완료조건을 만든다.
- 개선하고 그 조건으로 검증한다. 고칠 수 있는 미달만 한 번 더 개선한 뒤 다시 검증한다.
- 충족했거나, 남은 미달이 보존·불가이거나, 개선이 2회면 끝낸다.

## 완료 기준

- 확인한 사실, 해석, 미확인 사항을 구분한다.
- 결정과 우선순위에는 결과를 바꾸는 근거를 붙인다.
- 범위, 제외 범위, 사람의 결정이 필요한 항목과 검증 가능한 완료 조건을 남긴다.
- 공급자 공식 계약이 정본인 연동·이관 설계는 `ct-plan-ext`, Spring 코드 변경은 `ct-code-spring`의 범위로 남긴다.
- 저장 위치와 형식은 사용자 지정 또는 프로젝트 관례를 따른다.
