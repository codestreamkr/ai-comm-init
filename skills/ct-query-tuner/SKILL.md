# CT Query Tuner

데이터베이스 종류와 버전을 가정하지 않고 현재 환경에서 확인한다.

## 호출

- `$ct-query-tuner` 또는 `$ct-query-tuner ?`: 필요한 입력, 출력과 대표 예제를 안내한다.
- `$ct-query-tuner <쿼리 또는 대상>`: 튜닝 분석을 수행한다.

예제:

- `$ct-query-tuner 주문 조회 쿼리가 느린 원인을 분석해줘`
- `$ct-query-tuner src/main/resources/mapper/OrderMapper.xml의 findOrders`
- `$ct-query-tuner 이 실행 계획을 기준으로 개선안을 제안해줘`

## 자료 수집

- 쿼리와 실제 바인딩 조건
- DBMS와 버전, 드라이버와 프레임워크
- 테이블, 인덱스, 통계와 데이터 분포
- 실행 계획과 실제 수행 시간
- 호출 빈도, 반환 건수와 트랜잭션 맥락

수집할 수 없는 정보는 결과의 한계로 명시한다.

## 실행

1. 쿼리의 목적과 느린 조건을 확인한다.
2. 실행 계획과 스키마에서 병목 근거를 찾는다.
3. 영향이 작은 개선안부터 우선순위를 정한다.
4. 가능한 경우 동일 조건에서 변경 전후를 비교한다.

## 출력

- 환경과 분석 조건
- 병목 원인과 근거
- 우선순위가 있는 개선안
- 변경 영향과 주의점
- 검증 결과와 추가로 필요한 자료

## 완료 조건

- 개선안이 실행 계획 또는 측정 결과와 연결된다.
- 현재 DB 환경에서 적용 가능한 방법인지 확인된다.
- 추정과 확인된 사실이 구분된다.
