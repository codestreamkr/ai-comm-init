# 디자인 명세 작성 기준

- 사용자 서비스에 적용할 최종 규칙을 작성한다. 원본 `DESIGN.md`를 그대로 복사하지 않는다.
- 프로젝트의 기존 명세 형식과 토큰 이름을 우선한다. 아래 항목은 화면에 필요한 범위로 조정한다.
- 수치를 명세, 시안, 패턴 미리보기에 동일하게 적용한다. CSS 변수나 프로젝트 토큰을 공유해 불일치를 줄인다.
- 선택 전 문서는 제목에 초안임을 표시한다. 확정 문서는 최종 규칙만 담는다.

## 디자인 방향과 출처

- 서비스와 대상 화면.
- 분위기, 정보 밀도, 시각적 계층의 원칙.
- 주·보조 레퍼런스의 확인한 URL과 적용 요소.
- 분석 자료와 실제 사이트를 구분하고 공식 브랜드 가이드로 표현하지 않기.

## 의미별 디자인 토큰

| 분류 | 작성할 정보 |
| --- | --- |
| 색상 | 토큰명, HEX 또는 실제 색상값, 역할, 적용 대상 |
| 타이포그래피 | 폰트 스택, 한글·영문 대체 글꼴, 크기, 굵기, 행간, 자간 |
| 간격 | 간격 척도, 화면 여백, 섹션·요소 사이 간격 |
| 형태 | 모서리 반경, 테두리 두께와 색상 |
| 표면 | 배경·카드·오버레이 계층, 그림자 |
| 움직임 | 필요한 경우 지속 시간, 이징, 움직임 축소 동작 |

- 강조색, 본문, 보조 텍스트, 경계, 성공·주의·오류를 역할로 구분한다.
- 가독성을 확인한 색상 조합을 명시한다. 검증하지 않은 대비를 충족한다고 쓰지 않는다.
- 사용 불가능한 브랜드 전용 폰트를 기본 의존성으로 두지 않는다. 한글 텍스트의 줄바꿈과 폭을 확인한다.
- 숫자는 실제 시안에서 사용한 값으로 작성한다. 레퍼런스에서 확인한 값과 서비스에 맞게 선택한 값을 혼동하지 않는다.

## 레이아웃과 반응형 규칙

- 최대 콘텐츠 폭, 그리드, 열 간격, 정렬과 여백.
- 헤더, 탐색, 본문, 보조 영역의 역할과 배치.
- 실제 구현한 전환 기준과 모바일의 쌓임·접힘·탐색 방식.
- 표·목록·긴 제목·이미지의 좁은 화면 처리.
- 핵심 행동의 위치, 터치 영역과 키보드 탐색.

## 컴포넌트 규칙

- 화면에 필요한 버튼, 입력, 카드, 탐색, 배지, 표·목록 등을 정의한다.
- 크기, 간격, 텍스트, 색상과 변형별 사용 조건을 적는다.
- 필요한 기본·hover·focus·active·disabled 상태를 정의한다.
- 데이터나 폼이 있으면 선택·오류·로딩·빈 상태도 정의한다.
- 색상 이외의 오류 표시, 초점 표시와 접근 가능한 이름을 규정한다.

## 반복 디자인 패턴

- 각 패턴의 목적, 사용할 상황, 구성, 정보 우선순위, 반응형 동작을 적는다.
- 서비스에 필요한 패턴을 선택한다. 예: 검색·필터와 결과 목록, 지표와 상세 데이터, 소개와 주요 행동, 폼과 오류 안내.
- 서로 다른 정보 유형을 무조건 같은 카드 구조로 배치하지 않는다.
- 실제 화면 예와 피해야 할 사용법을 연결한다. 추상적인 분위기 형용사로 끝내지 않는다.

## 구현 지침

- 공통 토큰과 컴포넌트 재사용 규칙.
- 글꼴·이미지·아이콘의 사용 가능한 출처나 대안.
- 디자인을 유지하기 위한 사용·금지 규칙.
- 구현자가 따라야 할 명령이나 경로는 실제 프로젝트에서 확인한 내용만 기재한다.

## 패턴 미리보기 확인

- 의미별 색상 견본과 토큰명 표시.
- 한글·영문 제목, 본문, 보조 텍스트와 숫자 예시 표시.
- 주요 컴포넌트의 변형과 상태 표시.
- 반복 패턴을 사용자 서비스의 예시 콘텐츠로 표시.
- 화면 시안과 같은 토큰 사용 여부 확인.
- 데스크톱·모바일에서 렌더링과 넘침 확인.
- 비활성·오류·빈 상태가 정상 상태와 구분되는지 확인.
- 실제 데이터 처리 없이 미리보기만 구현한 동작은 명확하게 표시.
