# CT Review Log

지정한 코드의 로그를 프로젝트 규칙과 실제 처리 흐름에 맞춰 검토한다.

## 입력 확인

다음 입력으로 검토 범위를 확정한다.

- 필수 입력:
  - 클래스명, 메서드명, 함수명, 모듈명 또는 파일 경로 중 하나
- 선택 입력:
  - 클래스·파일 전체 또는 특정 메서드·함수 범위
  - 장애 조사, 운영 모니터링, 감사 추적 등 로그 목적
  - 운영 환경의 로그 수준과 출력 정책

저장소 검색으로 대상을 식별한다. 같은 이름의 후보가 여러 개이고 문맥으로 확정할 수 없을 때만 사용자에게 묻는다.

## 프로젝트 기준 확인

코드를 검토하기 전에 적용 기준을 확인한다.

1. 현재 작업 경로의 `AGENTS.md`와 연결된 프로젝트 문서를 읽는다.
2. 로깅, 예외 처리, 개인정보, 보안 규칙을 찾는다.
3. 의존성, import, 로거 선언과 설정 파일로 언어와 로깅 프레임워크를 판별한다.
4. 대상 코드와 로그 판단에 필요한 호출 관계를 확인한다.
5. 로그별 판정 전에 [로그 검토 기준](references/log-review-criteria.md)을 읽는다.

프로젝트의 명시적 규칙과 공통 로깅 모듈을 일반 기준보다 우선한다. 언어 또는 프레임워크를 확정하지 못하면 확인된 근거와 추정 범위를 결과에 표시한다.

## 검토 절차

### 1. 로그 목록 작성

대상 범위의 로그를 수집한다.

- 파일과 줄 번호
- 클래스·메서드·함수
- 현재 로그 수준과 메시지
- 인자, 예외 객체와 구조화 필드
- 실행 조건과 예상 발생 빈도
- 반복, 재시도, 비동기와 예외 처리 여부

### 2. 처리 흐름 파악

로그가 기록되는 상황과 최종 처리 결과를 코드로 확인한다.

- 정상 처리 시작, 완료와 주요 상태 변경
- 입력 오류와 업무 규칙 위반
- 복구 가능한 오류, fallback과 재시도
- 외부 시스템 호출과 트랜잭션 실패
- 상위 계층으로 전파되는 예외
- 반복 실행과 대량 처리

### 3. 로그별 판정

각 로그를 다음 중 하나로 판정한다.

- `유지`: 수준과 내용이 목적에 맞음
- `수준 변경`: 로그는 필요하지만 현재 수준이 부적절함
- `메시지 변경`: 사건, 대상, 결과 또는 원인 정보가 부족함
- `삭제`: 중복되거나 운영 가치가 없음
- `추가`: 장애 분석이나 상태 추적에 필요한 로그가 누락됨

수준뿐 아니라 예외 stack trace, 중복 기록, 민감정보, 구조화 필드, 지연 평가와 로그량을 함께 판정한다.

### 4. 변경안 작성

변경이 필요한 항목마다 다음 내용을 제시한다.

- 현재 위치와 코드
- 판정과 제안 수준
- 코드 흐름에 근거한 이유
- 해당 언어와 프레임워크에 맞는 제안 코드
- 운영 영향

사용자가 코드 수정을 명시적으로 요청하지 않으면 파일을 변경하지 않는다.

## 결과 형식

결과는 핵심 위험부터 작성한다.

### 검토 범위

- 대상 코드
- 판별한 언어와 로깅 프레임워크
- 확인한 호출 범위
- 적용한 프로젝트 규칙

### 요약

| 판정 | 건수 |
|---|---:|
| 유지 | 0 |
| 수준 변경 | 0 |
| 메시지 변경 | 0 |
| 삭제 | 0 |
| 추가 | 0 |

### 상세 검토

| 위치 | 현재 수준 | 제안 수준 | 판정 | 근거 |
|---|---|---|---|---|
| `파일:줄` | `info` | `debug` | 수준 변경 | 정상 호출마다 반복되며 운영 대응 대상이 아님 |

필요한 항목에는 현재 코드와 제안 코드를 함께 작성한다.

### 적용 우선순위

- `필수`: 민감정보 노출, 예외 유실, 장애 원인 확인 불가
- `권장`: 수준 부적절, 중복 기록, 과도한 로그량
- `선택`: 메시지와 구조화 필드 개선

### 확인 제한

실행 환경이나 운영 정책이 없어 판정하지 못한 항목만 기록한다.

## 완료 조건

- 지정된 범위와 관련 로그를 모두 확인했다.
- 언어와 로깅 프레임워크의 판별 근거를 확인했다.
- 각 변경 제안에 코드 근거와 운영 영향을 작성했다.
- 예외 중복과 stack trace 유실을 확인했다.
- 민감정보, 대량 로그와 불필요한 직렬화 위험을 확인했다.
- 수정 요청이 없으면 코드와 설정을 변경하지 않았다.
