# CT Journal

ct 스킬의 결정과 이해 상태를 기록한다.

- 진행 상태 표시는 [ct-progress](../ct-progress/SKILL.md)가 담당한다.
- 영구 기록은 저장소 루트의 `.debrief/`에 둔다.
- 최종 문서(`.docs/`)는 수정하지 않는다. 최종 문서에는 변경 이력을 쓰지 않는다.
- ADR의 확정과 내용 작성은 `ct-debrief`가 담당한다. 이 스킬은 저장 구조와 목록만 관리한다.
- 모든 기록은 `.debrief/`의 Markdown 파일에만 둔다. 사용자가 볼 수 없는 위치에 기록을 두지 않는다.
- 통계와 다른 스킬의 판단은 `.debrief/` 파일에서만 계산한다. 결과에는 근거 파일과 근거 실행을 붙인다.

## 호출

- 다른 ct 스킬은 이 파일을 상대 링크로 읽고 아래 지침을 따른다.
- `$ct-journal`: 아래 "통계"를 실행한다. 결과 아래에 요청 예제를 한 줄 붙인다.
- `$ct-journal <요청>`: 통계, 조회, 기간 요약, 점검 중 하나를 실행한다. 사용법을 물으면 역할, 필요한 입력, 대표 예제를 안내한다.

예: `$ct-journal 지난 7일의 결정과 남은 이해 부채를 요약해줘`

## 영구 기록

### 저장 구조

```text
.debrief/
├─ journal/YYYY-MM.md        # 실행 기록 (추가만)
├─ decisions/
│  ├─ README.md              # 유효 ADR 목록 (도메인별)
│  ├─ candidates.md          # 미확정 ADR 후보
│  ├─ NNNN-<제목>.md         # ADR
│  └─ archive/               # 대체됨·폐기 ADR
└─ debt.md                   # 이해 부채
```

- `.debrief/`가 없으면 첫 기록 때 만든다. 이때 `decisions/README.md`와 `decisions/candidates.md`를 빈 형식으로 함께 만든다.
- 기존 기록은 수정하지 않는다. 새 줄을 추가한다. 단, `README.md`, `candidates.md`, `debt.md`는 현재 상태로 갱신한다. 점검의 형식 변환도 예외다.

### 커밋 범위

| 저장소 | 커밋 | `.gitignore`에 추가 |
|---|---|---|
| 개인 저장소 | `.debrief/` 전체 | 없음 |
| 공유 저장소 | `.debrief/decisions/` | `.debrief/journal/`, `.debrief/debt.md` |

- `decisions/`는 팀 모두에게 필요한 결정과 이유다. `journal/`과 `debt.md`는 개인 기록이다.
- `.debrief/`를 처음 만들 때 저장소 성격을 판단한다. 근거가 없으면 `ct-plan`의 일괄 질문에서 받은 답을 쓴다. 단독 실행이면 그때 한 번 묻는다.
- 공유 저장소로 정하면 `.gitignore`에 두 줄을 추가한다. 이후에는 `.gitignore`를 보고 판단한다.

### 실행 기록 (`journal/YYYY-MM.md`)

- 스킬 실행이 끝날 때 한 번 기록한다. 단계마다 기록하지 않는다.
- 결론과 결정만 쓴다. 과정과 시행착오는 쓰지 않는다.
- 통계 도구가 읽으므로 아래 형식을 지킨다. 제목 줄은 `## <날짜> <run> · <스킬> · <작업 제목>`이다.

```markdown
## 2026-10-18 apply-1 · ct-apply · 주문 취소

- 결과: 완료 (단계 5/5, 검증 2회차 통과)
- 결정: 부분 환불 금액은 주문 항목 단위로 계산 → ADR 후보 c3
- 사용자 참여: 계획 승인
- 남은 항목: 없음

## 2026-10-18 debrief-1 · ct-debrief · 주문 취소

- 결과: 완료 (통과 표시)
- 이해 확인: 1/3
- 질문: 왜 · order · 정답 · 환불을 재고 복원보다 먼저 처리한 이유
- 질문: 만약 · order · 재질문 후 정답 · 부분 환불 금액이 0원일 때 처리
- 질문: 어디 · order · 오답 · 취소 가능 상태를 바꾸는 위치
- ADR: c3 · 확정 · 0007
- 부채: 추가 · order · 취소 가능 상태를 바꾸는 위치
- 남은 항목: 없음
```

| 항목 | 형식 | 쓰는 스킬 |
|---|---|---|
| 결과 | 첫 단어는 `완료` 또는 `중단`이다. 검증을 했으면 괄호 안에 `검증 N회차`를 쓴다. | 모두 |
| 결정, 사용자 참여, 남은 항목 | 자유 문장 | 모두 |
| 이해 확인 | `<첫 시도 정답 수>/<질문 수>` | `ct-debrief` |
| 질문 | `<유형> · <도메인> · <판정> · <질문 요지>`. 유형은 `왜`, `만약`, `어디`이다. 판정은 `정답`, `재질문 후 정답`, `오답`이다. | `ct-debrief` |
| ADR | `<후보 id> · <판정> · <ADR 번호 또는 판정 이유>`. 판정은 `확정`, `폐기`, `보류`이다. | `ct-debrief` |
| 부채 | `<추가 또는 해소> · <도메인> · <질문 요지>` | `ct-debrief` |

- 도메인은 ADR의 도메인과 같은 이름을 쓴다. 저장소의 도메인 이름이다.
- 질문, ADR, 부채는 항목마다 한 줄씩 쓴다.

### ADR 후보 (`decisions/candidates.md`)

- 맵에 보낸 ADR 후보를 실행이 끝날 때 이 파일에 반영한다. 맵 데이터는 지워지기 때문이다.
- 후보마다 다음 항목을 쓴다: id, 결정, 이유(사용자 답변 원문. 없으면 `(미정)`), 출처
- 이 파일의 후보는 모두 미확정이므로 상태 열을 두지 않는다. 형식은 [adr-format.md](../ct-debrief/references/adr-format.md)를 따른다.
- `ct-debrief`가 확정하거나 폐기한 후보는 이 파일에서 지운다. 처리 결과는 실행 기록에 남긴다.
- 작업 종료 때 처리하지 못한 후보는 남긴다. 다음 `ct-plan`이 계획에 포함해 처리한다.

### ADR 목록과 보관

- `ct-debrief`가 ADR을 확정하면 `decisions/README.md`에 도메인별로 추가한다.
- 대체됨이나 폐기 상태의 ADR은 `decisions/archive/`로 옮긴다. `README.md`에서도 지운다.
- 결정이 최종 문서에 현재 규칙으로 반영되면 해당 ADR을 `archive/`로 옮긴다.

### 이해 부채 (`debt.md`)

- `ct-debrief`에서 두 번 틀린 항목을 추가한다.
- 아래 표 형식으로 쓴다. 발생 실행은 `<날짜> <run>`으로 쓴다.

```markdown
# 이해 부채

| 도메인 | 관련 파일 | 질문 | 정답 요지 | 발생 실행 |
|---|---|---|---|---|
| order | src/order/OrderStatus.java | 취소 가능 상태를 바꾸는 위치 | `OrderStatus.isCancelable`을 고친다 | 2026-10-18 debrief-1 |
```
- 해소한 항목은 지운다. 해소 사실은 실행 기록에 남긴다.
- 대상 파일이 모두 삭제된 항목은 점검에서 종결한다.
- 기한과 개수 상한을 두지 않는다. 다음 `ct-plan`이 남은 항목을 계획에 포함한다.

## 통계

- 명령: `node <skill-dir>/scripts/stats.js <저장소> [--since YYYY-MM-DD] [--until YYYY-MM-DD]`
- 출력을 그대로 보여 준다. 수치를 다시 계산하거나 고치지 않는다.
- 출력 항목: 실행, 검증, 이해 확인(전체·월별·유형별·도메인별), 결정, 남은 항목, 보강 대상 도메인, 형식 외 기록
- 보강 대상 도메인 기준: 질문 2개 이상이고 첫 시도 정답률이 70% 미만이다. 또는 남은 이해 부채가 있다.
- "형식 외 기록"에 줄이 있으면 사용자에게 알린다. 그 줄은 집계에서 빠졌다.
- Node.js가 없으면 통계를 낼 수 없다. 사용자에게 알린다.

## 조회·요약·점검

| 요청 | 수행 |
|---|---|
| 조회 | `.debrief/` 기록에서 답한다. 답변에 근거 파일과 기록 날짜를 붙인다. |
| 기간 요약 | `journal/`에서 기간의 실행, 결정, 남은 후보, 남은 부채를 요약한다. |
| 점검 | 아래 항목을 확인하고 문제를 보고한다. |

점검 항목:

- `README.md`의 ADR 링크가 실제 파일을 가리킨다.
- `README.md`에 대체됨이나 폐기 상태의 ADR이 없다.
- `candidates.md`와 `debt.md`의 관련 파일이 존재한다.
- 각 ADR의 영향 문서가 존재한다.

- 기간 요약의 수치는 통계 명령에 `--since`, `--until`을 넣어 얻는다.
- 기간 요약과 부채 분류는 저가 모델 서브에이전트에 맡길 수 있다. 결과는 메인 에이전트가 근거와 대조한다.
- 점검에서 고칠 수 있는 항목은 사용자 확인 후 고친다. 파일 삭제는 하지 않는다.
- 점검에서 "형식 외 기록"이 있으면 형식 변환을 제안한다.
- 형식 변환은 "추가만" 규칙의 예외다. 내용은 바꾸지 않고 형식만 바꾼다.
- 원본에 없는 값은 쓰지 않는다. 바꿀 수 없는 줄은 그대로 둔다.
- 변환 전후를 표로 보여 주고 사용자 확인을 받는다. 확인 후 고친다.
- 변환 사실은 실행 기록에 새 항목으로 남긴다.

## 완료

- 통계: 통계 출력과 요청 예제 한 줄을 보고한다.
- 기록 요청: 기록한 파일 경로만 보고한다.
- 조회·요약: 답변과 근거 파일, 기준 시점을 보고한다.
- 점검: 문제 항목, 수정한 항목, 확인이 필요한 항목을 구분해 보고한다.
