# CT Code Tree

정본은 현재 코드에서 확인한 호출과 데이터 흐름이다. 운영 코드와 테스트는 수정하지 않는다.

## 호출

- `$ct-code-tree`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-code-tree <대상>`: 대상의 호출과 데이터 흐름을 분석한다.
- Claude Code는 `/ct-code-tree <대상>`로 호출한다. 호출 뒤 대상이 비어 있으면 안내만 하고 실행하지 않는다.

예: `$ct-code-tree OrderController.cancel의 호출 흐름을 분석해줘`

## 분석 기준

- 진입점과 사용자가 궁금한 범위를 먼저 식별한다. 같은 이름의 대상이 여럿이고 결과가 달라질 때만 사용자에게 확인한다.
- 의미 있는 분기, 상태 변화, 트랜잭션, 데이터 접근, 외부 I/O, 비동기 경계와 예외 흐름을 실제 코드 근거로 추적한다.
- 단순 위임과 접근자는 흐름 이해에 필요할 때만 포함한다.
- 동적 호출이나 런타임 설정처럼 정적으로 확정할 수 없는 연결은 추정하지 않고 미확인으로 남긴다.

## 결과

기본 산출은 대화다. 문서 요청이 있을 때만 프로젝트 관례에 맞는 Markdown 문서를 만든다.

- 시작점, 주요 호출 순서와 데이터 변화
- 결과를 바꾸는 분기와 실패 경로
- 외부 경계와 근거가 되는 파일·심볼
- 분석에서 제외한 범위와 미확인 연결
- 수행한 확인과 한계

표현 형식은 대상에 가장 잘 맞는 것을 선택한다. 호출 흐름 문서는 사용자 지정 또는 프로젝트 관례를 따르고, 없으면 `.docs/callTree-<진입점>-<대상>.md`에 저장한다. 기존 문서는 같은 대상인지 확인한 뒤에만 갱신한다.

테스트 작성은 `ct-code-tree-test`, 구조 전환 계획은 `ct-plan-work`의 범위로 남긴다.
