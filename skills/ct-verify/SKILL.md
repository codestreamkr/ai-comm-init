# CT Verify

확정된 요구사항과 실제 결과를 독립적으로 비교한다.

- 검증 자체는 구현 파일과 계획의 작업 상태를 변경하지 않는다.
- 실패 수정은 `ct-apply`에 맡긴다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력, 예제만 안내한다.
- 계획과 `ct-apply` 결과가 있으면 다음 항목을 확인한다: 요구사항, 완료 조건, 변경 결과, 검증 결과
- 계획과 결과가 없으면 사용자 요청, 프로젝트 문서, 테스트에서 검증 기준을 확인한다.
- 기준이 부족하면 추측하지 않는다. 사용자에게 확인한다.

예: `$ct-verify 주문 취소 기능이 계획의 요구사항을 충족하는지 검증해줘`

## 수행

- 요구사항마다 필요한 환경, 권한, 데이터를 확인한다.
- 현재 구현의 정상, 실패, 경계 흐름을 직접 검증한다.
- 코드 근거만으로 실행 결과를 단정하지 않는다.
- 각 요구사항을 통과, 실패, 미검증으로 구분한다.
- 테스트 명령이 성공해도 그것만으로 요구사항 전체를 통과로 처리하지 않는다.
- 실패 항목마다 다음 내용을 정리한다: 요구사항, 기대 결과, 실제 결과, 재현 조건, 실패 명령과 로그, 확인한 원인, 영향 범위
- 같은 작업 턴에서 [ct-apply](../ct-apply/SKILL.md)를 읽는다. 그 지침으로 실패 항목을 수정한다.
- 사용자가 수정 없이 검증만 요청했으면 실패를 보고만 한다.
- 수정 결과를 받으면 다음 테스트를 직접 다시 실행한다.
  - 실패한 테스트
  - 수정 영향 범위의 관련 테스트
- 영향을 받은 기존 판정은 새 결과로 갱신한다.
- 실패가 남으면 `ct-apply` 수정과 재검증을 반복한다. 이 반복은 `ct-verify`가 관리한다.

## 완료

- 다음 중 하나에 해당할 때까지 수정과 재검증을 계속한다.
  - 모든 요구사항이 통과했다.
  - 구체적인 장애로 더 진행할 수 없다. 예: 환경·권한·데이터 부족, 요구사항 결정 필요
- 실패 판정만으로 종료하지 않는다. 임의의 횟수 제한을 두지 않는다.
- 막힌 항목이 있어도 다른 검증은 계속한다.
- 검증만 요청받았으면 모든 요구사항에 다음 중 하나가 연결될 때 끝낸다.
  - 판정과 근거
  - 미검증 사유
- 다음 항목을 짧게 보고한다: 통과·실패·미검증 건수와 근거, 실패 재현 조건, 미검증 사유, 재개 지점
