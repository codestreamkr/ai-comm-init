# CT Verify

정본은 확정된 요구사항, 현재 코드와 실행 결과다. 요청한 범위의 검증을 끝까지 수행하며 코드·설정·테스트 파일과 계획의 작업 상태는 변경하지 않는다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력과 예제만 안내한다.
- 계획이 있으면 각 요구사항과 완료 조건을 읽는다. 계획이 없으면 사용자 요청에서 검증할 동작과 성공 기준을 확인한다.

예: `$ct-verify 주문 취소 기능이 계획의 요구사항을 충족하는지 검증해줘`

## 수행

- 각 요구사항을 실행 결과, 코드 근거 또는 구체적인 미검증 사유에 연결한다.
- 정상 흐름과 결과를 바꾸는 실패·경계 조건을 확인하고, 프로젝트에 있는 테스트·관측 수단을 사용한다.
- 테스트 실행 성공만으로 요구사항 전체를 통과 처리하지 않는다. 통과·실패·미검증을 구분하고 실패에는 재현 조건과 영향 범위를 남긴다.
- 검증 중 발견한 결함은 실패로 기록하고 재현 조건을 남긴다. 수정이 필요하면 해당 항목을 `ct-apply`에 넘기고 수정 후 다시 검증한다. 요구사항이나 범위가 달라져 판정할 수 없으면 해당 항목을 멈추고 확인받는다.

## 완료

- 모든 대상 요구사항에 판정과 근거가 연결될 때까지 검증한다. 임의의 개선 횟수로 종료하지 않는다.
- 환경·권한·자료 부족으로 실행할 수 없으면 미검증 사유, 필요한 조건과 재개 지점을 기록하고 가능한 검증은 계속한다.

## 결과 보고

- 요구사항별 통과·실패·미검증과 근거, 각 상태의 건수, 남은 위험을 짧게 보고한다.
- 실패한 항목은 `ct-apply`에서 수정할 수 있도록 재현 조건과 영향 범위를 명시한다.
