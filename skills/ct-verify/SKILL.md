# CT Verify

확정된 요구사항과 실제 결과를 독립적으로 비교한다.

- 검증 자체는 구현 파일과 계획의 작업 상태를 변경하지 않는다.
- 실패 수정은 `ct-apply`에 맡긴다.
- 진행 표시는 [ct-progress](../ct-progress/SKILL.md), `.debrief/` 기록은 [ct-journal](../ct-journal/SKILL.md) 지침을 따른다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력, 예제만 안내한다.
- 계획과 `ct-apply` 결과가 있으면 다음 항목을 확인한다: 요구사항, 완료 조건, 변경 결과, 검증 결과
- 계획과 결과가 없으면 사용자 요청, 프로젝트 문서, 테스트에서 검증 기준을 확인한다.
- 기준이 부족하면 추측하지 않는다. 연쇄 실행 중에는 계획의 완료 조건을 기준으로 쓰고 묻지 않는다. 그래도 판정할 수 없으면 미검증으로 표시한다.
- 단독으로 실행했고 기준이 부족하면 사용자에게 확인한다.
- `ct-apply`가 이 파일을 읽어 실행하면 판정만 반환한다. `ct-apply`를 다시 읽지 않는다. 수정과 재검증 반복은 `ct-apply`가 관리한다.

예: `$ct-verify 주문 취소 기능이 계획의 요구사항을 충족하는지 검증해줘`

## 수행

- 요구사항마다 필요한 환경, 권한, 데이터를 확인한다.
- 현재 구현의 정상, 실패, 경계 흐름을 직접 검증한다.
- 테스트 실행과 로그 요약은 가벼운 작업이다. 모델 선택은 [ct-apply](../ct-apply/SKILL.md)의 가벼운 작업 규칙을 따른다. 판정은 메인 모델이 한다.
- 코드 근거만으로 실행 결과를 단정하지 않는다.
- 각 요구사항을 통과, 실패, 미검증으로 구분한다.
- 테스트 명령이 성공해도 그것만으로 요구사항 전체를 통과로 처리하지 않는다.
- 실패 항목마다 다음 내용을 정리한다: 요구사항, 기대 결과, 실제 결과, 재현 조건, 실패 명령과 로그, 확인한 원인, 영향 범위
- 단독으로 실행했으면 같은 작업 턴에서 [ct-apply](../ct-apply/SKILL.md)를 읽는다. 실패 항목을 확정된 실패 수정 기준으로 넘긴다. 이후 수정과 재검증 반복은 `ct-apply`가 관리한다.
- 사용자가 수정 없이 검증만 요청했으면 실패를 보고만 한다.
- 재검증으로 실행되면 다음 테스트를 직접 다시 실행한다.
  - 실패한 테스트
  - 수정 영향 범위의 관련 테스트
- 영향을 받은 기존 판정은 새 결과로 갱신한다.

## 완료

- 모든 요구사항에 다음 중 하나가 연결되면 끝낸다.
  - 판정과 근거
  - 미검증 사유. 예: 환경·권한·데이터 부족, 요구사항 결정 필요
- 막힌 항목이 있어도 다른 검증은 계속한다.
- 수정이 필요한 실패가 남으면 단독 실행에서는 `ct-apply`에 넘긴다. 연쇄 실행에서는 판정을 `ct-apply`에 반환한다.
- 검증 보고는 요구사항별 표로 정리한다. 표 열은 다음 순서를 따른다: 요구사항, 판정, 검증 근거
- 판정에는 통과, 실패, 미검증 중 하나를 표시한다. 검증 근거에는 직접 확인한 코드나 실행 결과를 요약한다.
- 통과·실패·미검증 건수와 전체 테스트 결과는 표 아래에 짧게 설명한다. 실패 재현 조건, 미검증 사유, 재개 지점도 해당할 때 표시한다.
- 변경 요약은 표 아래에 수정 영역별로 보충한다. 요구사항 판정과 검증 근거를 반복하지 않고 다음 항목을 표시한다.
  - 논리 변경 요약: 변경 목적과 변경 전후 동작. 계획이 있으면 변경 예정 내용과 실제 결과를 비교한다.
  - 주요 코드 수정: 파일 경로, 메서드나 함수명, 수정 이유, 논리 변경 요약을 보충하는 코드 동작
- 메서드나 함수로 특정할 수 없는 코드는 해당 선언이나 설정 항목으로 표시한다.
- 변경 보고는 계획, 실제 변경 내역, 현재 코드에서 확인한 근거로 작성한다. 확인할 수 없는 항목은 확인 불가로 표시한다.
- 검증 중 수정한 코드도 포함한다. 확인한 코드 수정이 없으면 없다고 표시한다.

## 진행 표시

- 단독으로 실행하면 `ct-progress` 지침으로 맵에 실행을 보낸다. 단계는 이번에 검증할 요구사항을 검증 순서대로 잇는다.
- 단독 실행이 끝나면 `ct-journal` 지침으로 실행 기록을 남긴다.
- `ct-apply` 안에서 실행하면 별도 실행을 만들지 않는다. `ct-apply`의 검증 단계로 상태를 보낸다.
