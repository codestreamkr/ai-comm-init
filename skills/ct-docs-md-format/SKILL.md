  제공된 원본을 Markdown 파일로 변환하거나 기존 Markdown의 문체와 형식을 정리한다.
  원본의 내용과 의미를 보존하는 변환·가독성 개선 요청에 사용한다.
  코드 분석에 따른 기술문서 작성, 사실 수정, 내용 검토에는 사용하지 않는다.

원본의 내용과 의미를 보존하고 결과를 `.md` 파일로 저장하라.

## 범위와 저장

- 문서 작업에 지정된 원본과 대상, 적용할 프로젝트 지침을 확인하라.
- 스킬 자체의 검토·수정 요청은 문서 실행 요청과 구분하라.
- 사용자 지정 경로를 우선하라. 기존 문서가 대상이면 같은 파일을 수정하라.
- 변환할 원본에 대응하는 `.md` 파일이 명확하면 그 파일을 사용하라.
- 새 파일은 프로젝트 문서 배치와 파일명 규칙을 따라라. 규칙이 없으면 `docs/`에 원본 이름으로 저장하라.
- 원본 이름이 없으면 내용을 나타내는 파일명을 정하라. 대상 파일이나 경로가 충돌하면 확인 후 저장하라.

## 허용하는 변경

- 중복 수식과 완곡한 표현을 줄이고 적용되는 문체 지침에 맞춰 문장을 정리하라.
- 사실·조건·근거·적용 범위가 모두 같은 중복만 통합하라. 구분이 불확실하면 보존하라.
- 나열은 목록, 순서는 번호 목록, 비교·대응은 표로 표현하라. 기존 형식이 목적에 맞으면 유지하라.
- 원본의 코드·로그·명령어·설정 예시는 언어를 지정한 코드 블록으로 표현하라.
- 같은 문단의 소스 줄바꿈은 soft break를 사용하라. 원본의 의도적인 hard break는 보존하라.
- 링크·경로·식별자·코드 토큰은 중간에서 나누지 마라.

## 보존과 검증

- 사실·결정·요구사항·상태·우선순위·정보 순서와 의존 관계를 보존하라.
- 수치·날짜·경로·URL·코드·명령어·식별자·고유 명칭을 보존하라.
- 기존 제목과 계층, 목록 순서와 들여쓰기 관계를 보존하라.
- YAML·HTML·MDX·템플릿 지시문·주석·참조 링크·각주·제목 ID·작업 목록 상태를 보존하라.
- 새 사실·의도·동작·예시를 추가하지 마라. 내용 오류는 수정 범위에 넣지 말고 결과에 알려라.
- 저장 후 원본과 대조하여 누락·의미 변경·링크 손상과 Markdown 구조를 확인하라.
- 검증에서 발견한 형식 문제를 수정하라. 해결하지 못한 문제는 완료 여부와 구분해 보고하라.
- 결과에는 파일 경로, 검증 결과, 유지한 내용 오류와 미검증 사항만 보고하라. 해당하지 않는 항목은 생략하라.
