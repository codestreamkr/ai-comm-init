# Markdown 문서 생성 및 포맷 정리

결과는 답변에만 쓰지 않는다. 반드시 `.md` 파일로 저장한다.

## 요청 범위

- 스킬 실행 요청과 스킬 수정 요청을 구분한다.
- 사용자가 이 스킬의 수정을 요청하면 스킬 파일만 수정한다.
- 스킬 수정 요청에 첨부된 소스나 Markdown 파일은 동작 예시로만 사용한다.
- 문서 생성·수정을 명시적으로 요청하지 않으면 첨부 파일과 결과 문서를 만들거나 수정하지 않는다.

## 출력 파일 결정

1. 사용자가 출력 파일을 지정하면 그 파일을 사용한다.
2. 기존 Markdown 파일이 대상이면 그 파일을 같은 위치에서 수정한다.
3. 원본이 Markdown이 아니면 같은 이름의 `.md` 파일을 찾는다. 파일이 있으면 그 파일과 폴더를
   유지하고 수정한다.
4. 대상 `.md` 파일이 없으면 저장소의 문서 배치·파일명 규칙을 따른다. 필요한 폴더가 없으면
   만든다. 별도 파일명 규칙이 없으면 원본 파일명을 기준으로 파일 이름을 정한다.
5. 저장소에 문서 배치 규칙이 없으면 저장소 루트의 `docs` 폴더에 만든다.

다음 경우에는 파일을 임의로 덮어쓰지 않는다. 사용자에게 확인한다.

- 연관된 기존 문서가 여러 개인 경우
- 출력 위치 규칙이 충돌하는 경우

## 내용 작성 범위

- 기존 Markdown 파일은 그 파일만 읽는다. 형식과 문체만 정리한다.
- 비 Markdown 원본에서 문서를 만들 때는 원본에서 확인한 사실만 사용한다.
- 원본에서 확인할 수 없는 의도, 동작, 요구사항을 추정해 추가하지 않는다.
- 형식은 대상 문서와 요청에 맞춘다.
- 비교·대응 관계는 표로 정리한다. 절차는 순서 목록으로 정리한다.
- 코드, 명령어, 조건 분기 예시는 코드블록으로 쓴다. 원본에 없는 코드를 만들어 설명을
  대체하지 않는다.
- 기존 형식이 더 알맞으면 기존 형식을 유지한다.
- 문체는 전역 `문서 작성` 기준을 따른다. 기존 문체와 다르면 STE를 따른다.
- 내용과 의미는 바꾸지 않는다.

## 완료조건

- 자료를 수집한 뒤 이번 요청의 완료조건을 만든다.
- 문서를 개선하고 완료조건으로 검증한다.
- 고칠 수 있는 미달 항목이 있으면 한 번 더 개선하고 다시 검증한다.
- 다음 중 하나에 해당하면 끝낸다.
  - 완료조건을 모두 충족했다.
  - 남은 미달 항목이 보존 대상이거나 고칠 수 없다.
  - 개선을 2회 했다.

## 작업 절차

1. 요청이 스킬 수정인지 문서 작업인지 구분한다.
2. 문서 작업이면 출력 파일과 폴더를 정한다.
3. 대상 문서 또는 원본을 읽고 자료를 수집한다.
4. 기존 문서는 형식과 문체만 정리한다. 새 문서는 원본에서 확인한 내용만 구조화한다.
5. 결과를 정한 `.md` 파일에 저장한다. 그 다음 완료조건을 따른다.

## 결과

완료 후 아래 항목만 짧게 보고한다.

- 파일 경로
- 유지한 내용 오류
