# CT External Architect

프로젝트의 기존 연동 구조와 현재 공급자 계약을 근거로 설계한다.

## 호출

- `$ct-external-architect` 또는 `$ct-external-architect ?`: 입력, 출력과 대표 예제를 안내한다.
- `$ct-external-architect <연동 요청>`: 분석과 설계를 수행한다.

예제:

- `$ct-external-architect 기존 PG 연동을 새 공급자로 이관하는 계획을 작성해줘`
- `$ct-external-architect 결제 승인·취소 연동 구조를 검토해줘`

## 자료 수집

- 적용되는 프로젝트 규칙 문서
- 기존 어댑터, 설정, 인증, 요청·응답과 오류 처리
- 데이터 저장, 재시도, 멱등성과 보상 흐름
- 대상 공급자의 현재 공식 API 문서와 변경 정보
- 기존 테스트, 모니터링과 운영 제약

## 실행

1. 현재 연동 경계와 계약을 코드에서 확인한다.
2. 공급자 공식 자료에서 필요한 현재 계약을 확인한다.
3. 유지할 내부 계약과 변경할 외부 계약을 구분한다.
4. 구현 경계, 단계별 이관과 검증 계획을 작성한다.

## 출력

- 현재 구조와 근거
- 목표 연동 구조
- 인터페이스와 데이터 매핑
- 오류, 재시도와 운영 고려사항
- 이관 순서와 검증 기준
- 확인이 필요한 공급자 계약

## 완료 조건

- 설계가 현재 프로젝트와 공급자 공식 자료에 근거한다.
- 내부 영향과 외부 계약 변경이 구분된다.
- 구현·전환·검증 단계가 연결된다.
