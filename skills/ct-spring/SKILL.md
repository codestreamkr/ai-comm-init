# CT Spring

현재 프로젝트에서 확인한 Spring 환경과 기존 코드 패턴을 기준으로 작업한다.

## 호출

- `$ct-spring` 또는 `$ct-spring ?`: 사용법과 대표 예제를 안내한다.
- `$ct-spring component ?`: 컴포넌트 작업의 입력, 출력과 예제를 안내한다.
- `$ct-spring <요청>`: Spring 작업을 수행한다.
- `$ct-spring component <요청>`: 공통 컴포넌트를 프로젝트 방식에 맞춰 적용한다.

예제:

- `$ct-spring 주문 취소 트랜잭션을 구현해줘`
- `$ct-spring Security 설정을 검토해줘`
- `$ct-spring component API 예외 응답 처리를 추가해줘`

## 자료 수집

- 적용되는 프로젝트 규칙 문서
- 빌드 파일과 dependency lock
- Java, Spring Boot와 관련 라이브러리의 실제 버전
- 설정 파일, 패키지 구조와 동일 역할의 기존 코드
- 테스트 구성과 프로젝트 검증 명령

프로젝트 근거만으로 API 선택을 확정하기 어려우면 확인된 버전의 공식 문서를 조회한다.

## 실행

1. 프로젝트 환경과 요청 대상을 확인한다.
2. 같은 역할을 하는 기존 구현과 관례를 찾는다.
3. 확인된 버전과 구조에 맞는 구현을 선택한다.
4. 영향 범위 안에서 반영하고 프로젝트 방식으로 검증한다.

## 출력

- 확인한 프로젝트 환경
- 변경 또는 검토 결과
- 선택 근거와 영향 범위
- 검증 결과와 확인 필요 항목

## 완료 조건

- 구현이 현재 프로젝트의 버전과 관례에 맞는다.
- 관련 설정, 호출부와 테스트 영향이 함께 확인된다.
- 가능한 프로젝트 검증을 통과했거나 실행하지 못한 이유가 보고된다.
