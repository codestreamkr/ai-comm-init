# 개발자용 기술문서 작성

개발자가 전체 동작과 기능 간 관계를 이해하고, 변경할 위치와 영향을 찾을 수 있는 기술문서를 작성하라.

## 근거 확인

- 관련 문서와 코드·설정을 확인하라. 대표 진입점에서 주요 호출·분기·외부 연동·데이터 변경을 추적하라.
- 실제 구현과 외부 규격을 구분하라. 외부 규격은 적용 버전의 공식 자료로 확인하라.
- 현재 동작과 개발 요구를 구분하라. 확인하지 못한 동작과 설계 의도를 사실로 단정하지 마라.

## 내용 선택과 설명

- 생략하면 동작 이해나 변경 판단이 달라지는 정보만 본문에 포함하라. 개념·데이터·규칙·예외·제약에 모두 적용하라.
- UI와 구현 세부사항도 같은 기준으로 선택하라. 화면 요소나 코드 항목의 단순 나열은 제외하라.
- 코드의 실행 순서를 업무 의미로 재구성하라. 선행 조건·판단·처리·결과를 인과관계로 연결하라.
- 분기는 경로별 조건과 결과를 구분하라. 경로가 다시 합류하는 지점과 합류 후 상태를 밝혀라.
- 판단 이유는 확인한 근거와 연결해 설명하라.
- 전체 흐름과 결과를 이해하는 데 필요한 분기·데이터 변경·실패 영향을 보존하라.
- 값을 만드는 처리, 값을 바꾸는 처리, 결과를 확정하는 처리를 구분하라. 예: 금액 계산, 주문 준비, 결제 확정
- 외부 시스템으로 이어지는 처리는 호출 시점, 전달 값, 실패 시 상태를 설명하라.

## 문서 구성

전체에서 상세로 이어지도록 구성하라. 다음은 참고 순서이며 고정 목차가 아니다.

1. 전체 구조와 흐름
   - 목적과 범위, 구성 요소의 책임, 주요 단계와 분기의 연결
2. 기능별 상세 동작
   - 역할과 선행 조건, 입력과 출처, 판단과 처리, 결과와 후속 영향, 관련 구현
3. 주요 항목과 관계
   - 동작 이해에 필요한 개념·데이터·규칙의 의미와 관계
4. 예외·제약과 변경 시 확인사항
   - 여러 기능에 걸친 실패 영향과 복구, 공통 제약, 변경 영향과 검증 기준

- 기능별 설명은 해당 부분만 읽어도 역할·조건·처리·결과와 앞뒤 연결을 이해할 수 있게 작성하라.
- 기능에 속한 내용은 해당 기능에서 설명하라. 공유 정보는 공통 설명으로 연결해 중복을 줄여라.
- 문서 목적에 따라 항목을 합치거나 생략하라. 모든 기능에 같은 하위 제목을 적용하지 마라.

## 표현과 가독성

- 제목은 기능·처리·판단 대상을 드러내도록 작성하라. 제목 계층으로 전체 흐름과 세부 설명을 구분하라.
- 각 절은 핵심 동작이나 결론으로 시작하라. 상세 조건과 구현 설명은 뒤에 배치하라.
- 문단마다 한 가지 주제를 설명하라. 조건과 예외는 관련 처리 가까이에 배치하라.
- 처리 순서는 번호 목록으로, 병렬 항목은 글머리 목록으로 표현하라.
- 표는 짧은 비교에만 사용하라. 셀은 한 구절 이하, 열은 4개 이하로 제한하라.
- 기준을 넘는 조건·필드·경로는 항목별 세로 목록으로 나눠라.
- 단계·분기·관계가 글보다 명확해질 때 다이어그램을 사용하라. 한 그림에 여러 기능의 세부 처리를 몰아넣지 마라.
- 요약·표·그림에도 결과를 바꾸는 조건과 분기 우선순위를 유지하라.
- 핵심 결론과 중요한 제약만 굵게 강조하라. 식별자·설정 키·코드값은 인라인 코드로 구분하라.
- 코드 예시는 필요한 부분만 언어 지정 코드 블록으로 제시하라.
- 구현·검증·관련 문서 링크는 해당 설명 가까이에 두고 용도를 붙여라. 예: `OrderService.java` (금액 계산)
- 한 곳에 링크를 3개보다 많이 나열하지 마라. 넘는 링크는 관련 기능 절로 나눠라.
- 문서 분량과 탐색 필요에 따라 목차와 절 간 링크를 제공하라.
- 같은 설명을 형식만 바꿔 반복하지 마라.

## 완료 확인과 저장

- 문서만 읽고 전체 흐름과 기능별 조건·처리·결과를 설명하고, 변경 위치와 영향을 찾을 수 있는지 확인하라.
- 값·산식·상태·코드 위치와 그 의미가 근거와 일치하는지 확인하라. 링크가 가리키는 대상도 확인하라.
- 각 절에 선정 기준을 다시 적용하라. 생략해도 판단이 같은 내용은 지워라.
- 링크한 문서, 같은 대상을 다루는 문서와 내용이 충돌하지 않는지 확인하라.
- 표가 셀·열 기준 안인지 확인하라. 코드 블록 줄이 가로 스크롤 없이 읽히는지 확인하라.
- 사용자가 지정한 파일과 위치를 우선하라. 새 문서는 저장소의 문서 배치와 파일명 규칙을 따라라.
- 결과를 Markdown 파일로 저장하고 경로를 보고하라. 필요한 미확인·미검증 사항은 짧게 밝혀라.
