# CT Data Query

정본은 현재 DB 환경, 스키마, 쿼리, 실행 계획과 측정 결과다. DBMS와 버전을 가정하지 않는다.

## 호출

- `$ct-data-query`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-data-query <요청>`: 대상 쿼리의 병목을 분석하고 개선안을 검증한다.
- Claude Code는 `/ct-data-query <요청>`로 호출한다. 호출 뒤 요청이 비어 있으면 안내만 하고 실행하지 않는다.

예: `$ct-data-query OrderMapper.xml의 findOrders가 느린 원인을 분석해줘`

## 판단

- 쿼리 위치, 실행 환경, 대표 입력과 성능 증상을 프로젝트와 요청에서 찾는다.
- 실행 계획이나 측정이 없으면 가능한 근거를 수집하고, 확보하지 못한 원인은 추정으로 분리한다.
- 기본은 읽기 전용 분석이다. 저장소의 쿼리 변경이 명시되면 필요한 범위만 수정하고, 운영 DB의 DDL·데이터 변경은 수행하지 않는다.
- 앱 구조 변경은 `ct-code-spring`의 범위로 남긴다.

## 완료 기준

- 병목 판단을 실행 계획, 측정, 스키마와 데이터 분포 중 확인한 근거에 연결한다.
- 개선안은 우선순위, 기대 효과, 부작용과 적용 조건을 포함한다.
- 변경 전후를 가능한 한 같은 조건으로 비교하고 결과 의미가 유지되는지 확인한다.
- 직접 측정하지 못한 모든 개선안은 검증된 결과가 아닌 추정으로 표시한다.
- 분석 조건, 결과, 검증 수치와 수집하지 못한 조건을 보고한다.
