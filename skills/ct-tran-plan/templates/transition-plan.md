# 전환 계획 문서 템플릿

아래 골격에서 필수 섹션은 유지하고 조건부 섹션은 코드와 사용자 요구로 확인된 경우에만 사용한다.

## 구성

- 파일명과 갱신 대상 판정
- 필수·조건부 허용 섹션
- 문서 골격과 섹션 작성 기준

## 파일 적용 기준

- 수집한 후보에 동일 대상 문서가 없으면 `.docs/plans/{doc_prefix}_tobe_{target_id}_transition_plan.md`를 생성한다.
- `target_id`는 `SKILL.md`의 source path·FQCN·완전 시그니처 기반 SHA-256 규칙을 적용한다.
- 기본 경로가 다른 대상과 충돌하면 `SKILL.md`의 hash 길이 확장 규칙으로 충돌 없는 신규 경로를 정한다.
- `.docs/plans/`, `.0_my/plans/`, 작업 루트와 저장소 전체에서 기본·legacy 후보를 수집하고 fully qualified class name, 완전한 메서드 시그니처와 소스 경로가 같은 문서 하나만 갱신한다.
- 불일치 후보 파일은 보존하고, 동일 대상 문서가 여러 개이거나 동일성을 확정할 수 없으면 갱신 전에 사용자에게 확인한다.
- 사용자가 지정한 기존 파일도 대상 동일성을 확인한 뒤 갱신한다.
- 별도 신규본은 사용자가 새 파일을 명시한 경우에만 만든다.

## 허용 섹션

아래 표를 문서 섹션 화이트리스트로 사용한다.

| 구분 | 섹션 | 적용 기준 |
|---|---|---|
| 필수 | 대상 식별 | fully qualified class name, 완전한 메서드 시그니처, 소스 경로, target hash |
| 필수 | 목적 | 대상과 전환 목적 |
| 필수 | 전체 흐름 기준 | 유지할 처리 순서와 실패 기준 |
| 필수 | 현재 CallTree | 실제 코드 기준 2depth 흐름 |
| 필수 | 현재 구조 판단 | 문제점과 코드 근거 |
| 필수 | 목표 CallTree | 목표 책임 경계와 유지 계약 |
| 필수 | 전환 기준 | 기존 유지 항목과 신규 제안 |
| 필수 | 변경 효과 | 현재 문제와 목표 경계에 연결된 효과 |
| 필수 | 서비스 책임 | 목표 서비스의 책임과 출력 |
| 필수 | 진입점 책임 | 대상 진입점의 유지·이관 책임. Controller는 `컨트롤러 책임`으로 표기 |
| 필수 | 검증 책임 | 검증 위치와 책임 경계 |
| 필수 | 현재 메서드 매핑 | 기존 위치와 목표 서비스·기준 메서드 또는 로직 |
| 필수 | 응답 유지 기준 | 응답·상태 코드 또는 실행 결과 계약 |
| 필수 | 테스트케이스 기준 | 회귀 검증 대상과 기준 |
| 필수 | 운영 로그 기준 | 식별자, 단계값과 결과 기록 기준 |
| 필수 | 이력관리 | 최종 변경 요약 |
| 조건부 | 입력 기준 | 입력 구조 유지가 핵심 판단인 경우 |
| 조건부 | 처리 단계값 | 실제 흐름에 적용할 단계값이 있는 경우 |
| 조건부 | 실패·보상 처리 기준 | 실패·보상 흐름이 코드에서 확인된 경우 |
| 조건부 | 확인 필요 | 코드와 프로젝트 문서로 확정할 수 없는 항목이 있는 경우 |

## 섹션 적용 기준

- `대상 식별`은 기존 문서의 갱신 대상 판정에 사용하는 값이므로 실제 코드 기준으로 작성한다.
- `목적`에는 대상과 전환 목적만 쓴다.
- 현재 CallTree는 루트 기준 2depth까지만 작성한다.
- 현재 구조 판단은 문제점과 코드 근거를 연결한다.
- 목표 CallTree는 현재 책임을 목표 경계로 옮긴 필수 산출물로 작성한다.
- 기존 유지 항목과 신규 제안을 구분한다.
- Controller가 대상이면 `진입점 책임`을 `컨트롤러 책임`으로 바꾼다.
- 목표 CallTree와 서비스 책임이 중복되면 목표 CallTree의 흐름은 유지하고 세부 책임 설명은 서비스 책임 표에만 적는다.
- `응답 유지 기준`은 코드에서 확인한 계약을 기록하고, 응답·상태 코드의 존재 또는 유지 여부를 확정할 근거가 없으면 추측하지 않고 `확인 필요`로 판정한다.
- 입력 구조 유지가 핵심 판단일 때만 `입력 기준`을 사용하고, 아니면 해당 섹션을 제외한다.
- 실패·보상 흐름이 없으면 해당 섹션을 제외한다.
- 확인할 항목이 없으면 `확인 필요`를 제외한다.
- 문서 본문에는 최종안만 남긴다.
- 문서 끝에는 `## 이력관리`를 두고 `- YYYY-MM-DD: 변경 내용 요약` 형식으로 기록한다.
- 같은 날짜의 이력이 있으면 기존 날짜 항목에 변경 내용을 합친다.
