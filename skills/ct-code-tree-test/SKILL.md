# CT Code Tree Test

정본은 현재 운영 코드, 호출 흐름과 프로젝트의 기존 테스트 관례다. 별도 요청이 없으면 운영 코드를 수정하지 않는다.

## 호출

- `$ct-code-tree-test`: 역할, 필요한 입력과 대표 예제를 안내한다. 실행하지 않는다.
- `$ct-code-tree-test <요청>`: 대상 흐름의 테스트를 만들거나 고치고 검증한다.
- Claude Code는 `/ct-code-tree-test <요청>`로 호출한다. 호출 뒤 요청이 비어 있으면 안내만 하고 실행하지 않는다.

예: `$ct-code-tree-test .docs/callTree-OrderController-cancel.md를 근거로 테스트를 작성해줘`

## 판단

- 호출 흐름 문서가 있어도 테스트할 핵심 호출과 분기를 현재 코드에서 다시 확인한다.
- 문서가 없거나 현재 코드와 다르면 현재 코드에서 테스트에 필요한 흐름만 확인한다. 전체 분석 문서가 필요하면 `ct-code-tree`의 범위로 남긴다.
- 분기, 상태 변화, 계산, 외부 연동과 예외처럼 관찰 가능한 동작을 우선한다. 단순 구현 세부사항을 고정하지 않는다.
- 사용자 흐름 전체의 QA는 `ct-qa-flow`의 범위로 남긴다.

## 완료조건

- 자료를 수집한 뒤 이번 요청의 완료조건을 만든다.
- 개선하고 그 조건으로 검증한다. 고칠 수 있는 미달만 한 번 더 개선한 뒤 다시 검증한다.
- 충족했거나, 남은 미달이 보존·불가이거나, 개선이 2회면 끝낸다.

## 완료 기준

- 기존 테스트 스택, 위치, 이름과 패턴을 따른다.
- 정상 경로와 대상 위험에 필요한 실패·경계 경로를 선택한다.
- 테스트가 실제 운영 코드의 동작을 검증하는지 확인하고 가능한 범위의 관련 테스트를 실행한다.
- 변경한 테스트, 고정한 동작, 실행 결과와 미검증 범위를 보고한다.

- 실행 결과
