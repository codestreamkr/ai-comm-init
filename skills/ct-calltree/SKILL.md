# CT CallTree

현재 프로젝트의 코드와 규칙을 근거로 호출 흐름 작업을 수행한다.

## 호출

- `$ct-calltree` 또는 `$ct-calltree ?`: 작업 목록과 대표 예제를 안내한다.
- `$ct-calltree <작업> ?`: 해당 작업의 입력, 출력, 예제를 안내한다.
- `$ct-calltree <작업> <대상>`: 지정한 작업을 실행한다.
- 작업 없이 요청이 이어지면 요청 내용에 맞는 작업을 선택한다.

## 작업

- `analyze`: 진입점부터 의미 있는 호출과 데이터 흐름을 분석한다.
  - 예: `$ct-calltree analyze OrderController.cancel`
- `transition`: 현재 구조와 목표 구조를 비교해 전환 계획을 작성한다.
  - 예: `$ct-calltree transition OrderService.cancel`
- `test`: 호출 흐름과 운영 코드를 근거로 필요한 테스트를 작성하고 검증한다.
  - 예: `$ct-calltree test .docs/order-cancel-calltree.md`

## 자료 수집

작업에 필요한 범위만 프로젝트에서 확인한다.

- 적용되는 프로젝트 규칙 문서
- 빌드 파일, 소스 루트와 테스트 구조
- 대상 심볼의 선언, 호출자, 피호출자와 데이터 변경 지점
- 관련 설정, 예외 처리와 기존 테스트
- 동일한 역할을 하는 기존 문서와 코드 패턴

프로젝트에서 확인되지 않는 버전, 패키지, 경로와 정책은 가정하지 않고 확인 필요 항목으로 분리한다.

## 실행

1. 대상 심볼과 작업 범위를 확정한다.
2. 실제 코드에서 필요한 깊이까지 호출과 데이터 흐름을 추적한다.
3. 선택한 작업에 필요한 결과를 작성한다.
4. 기존 프로젝트의 빌드와 테스트 방법으로 가능한 검증을 수행한다.

## 출력

- 분석 대상과 근거 경로
- 호출 흐름 또는 전환·테스트 결과
- 수행한 검증
- 확인이 필요한 항목

문서 경로와 형식은 사용자 지정 또는 프로젝트의 기존 패턴을 사용한다.

## 완료 조건

- 대상과 호출 관계가 실제 코드에 근거한다.
- 선택한 작업의 결과가 요청 범위를 충족한다.
- 검증 결과와 미확인 항목이 구분된다.
