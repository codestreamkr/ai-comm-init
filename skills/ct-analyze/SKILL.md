# CT Analyze

현재 코드, 설정, 테스트를 근거로 실제 동작을 분석한다. 사용자가 요청한 분석 문서만 만들거나 갱신한다. 코드, 설정, 테스트는 변경하지 않는다. 확인하지 않은 의도를 사실로 쓰지 않는다.

진행 표시는 [ct-progress](../ct-progress/SKILL.md), `.debrief/` 기록은 [ct-journal](../ct-journal/SKILL.md) 지침을 따른다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력, 예제만 안내한다.
- `ct-plan`이 이 파일을 읽어 실행하면 문서 저장 여부를 묻지 않는다. 분석 결과는 계획의 근거로 쓴다.
- 단독으로 실행하면 분석 요청에 문서 생성 여부가 없을 때 문서로 저장할지 사용자에게 묻는다. 답변을 받은 뒤 분석을 진행한다.
- 사용자가 문서 생성 여부를 이미 지정했으면 다시 묻지 않는다.
- 대상이 있으면 진입점과 범위를 정하고 조사한다.
- 대상이 여러 개이고 대상에 따라 결과가 달라질 때만 사용자에게 확인한다.

예: `$ct-analyze OrderController.cancel의 호출과 데이터 흐름을 분석해줘`

## 수행

- 진입점에서 시작해 다음 항목을 추적한다.
  - 결과를 바꾸는 호출과 분기
  - 데이터와 상태의 변화
  - 외부 호출, 비동기 처리, 예외의 경계
- 관련 설정과 테스트를 확인한다.
- 여러 위치의 파일 탐색은 가벼운 작업이다. 모델 선택은 [ct-apply](../ct-apply/SKILL.md)의 가벼운 작업 규칙을 따른다. 결론은 메인 모델이 코드 근거와 대조해 내린다.
- `.debrief/decisions/README.md`에서 대상 도메인의 유효 ADR을 읽는다. 결정 이유가 필요한 결론에 ADR 번호를 붙인다.
- `.debrief/debt.md`에서 대상 영역의 이해 부채를 확인한다. 해당 항목은 보고에 포함한다.
- `.debrief/`가 없으면 결정 기록 확인을 건너뛴다.
- 각 결론에 파일과 심볼 근거를 붙인다.
- 정적으로 확인할 수 없는 연결은 미확인으로 표시한다.

## 완료

- 요청한 주요 경로를 모두 확인할 때까지 진행한다.
- 대화 보고는 주요 기능별 표로 정리한다. 표 열은 다음 순서를 따른다: 주요 기능, 처리 흐름, 영향·위험, 코드 근거, 결정 근거
- 코드 근거에는 파일 경로와 메서드나 함수명을 표시한다.
- 결정 근거에는 관련 ADR 번호를 표시한다. 관련 ADR이 없으면 `-`로 표시한다.
- 대상 영역의 이해 부채가 있으면 표 아래에 항목을 나열한다.
- 검증 결과와 미확인 사항은 표 아래에 짧게 설명한다. 진행이 막히면 확인한 범위, 남은 경로, 막힌 이유, 재개 지점도 표시한다.
- 표의 내용을 보충 설명에서 반복하지 않는다.
- 문서를 생성하기로 했으면 분석 결과를 Markdown 파일로 저장한다. 저장 위치는 사용자 지정 위치나 프로젝트 문서 관례를 따른다.
- 저장 위치를 정할 근거가 없으면 사용자에게 확인한다.
- 문서를 저장했으면 대화 보고에 문서 경로를 포함한다.

## 진행 표시

- 단독으로 실행하면 `ct-progress` 지침으로 맵에 실행을 보낸다. 단계는 이번 분석에서 실제로 추적할 경로로 만든다.
- 단독 실행이 끝나면 `ct-journal` 지침으로 실행 기록을 남긴다.
- `ct-plan` 안에서 실행하면 별도 실행을 만들지 않는다. `ct-plan`의 분석 단계로 상태를 보낸다.
