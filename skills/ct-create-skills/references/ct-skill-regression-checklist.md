# CT 스킬 기능 보존 체크리스트

기존 CT 스킬을 수정하기 전에 현재 기능 계약을 고정하고 변경 후 같은 기준으로 대조한다.

## 변경 전 기능 계약

스킬별로 아래 항목을 현재 파일과 Git 기준 버전에서 수집한다.

- 트리거: `$ct-*` 명시 호출과 `allow_implicit_invocation: false`
- 입력: 필수값, 선택값, 모호할 때 질문 기준
- 참조: 항상 읽는 파일과 조건부로 읽는 파일, 직접 연결된 `references/`, `templates/`, `workflow/`, `components/` 문서의 본문
- 출력: 파일 경로, 파일명, 필수 섹션과 대화 보고
- 쓰기 범위: 생성, 갱신, 보존, 사용자 확인이 필요한 변경
- 완료 조건: 필수 검증과 실행하지 못했을 때 보고
- 호환성: legacy 경로, 구형 문서와 기존 프로젝트 fallback
- 차단 규칙: 추측 생성, 중복 생성, 민감정보, 범위 확대 방지

## 변경 규칙

1. 삭제할 상세 규칙이 있으면 먼저 하나의 reference 또는 template 정본으로 옮긴다.
2. `SKILL.md`에서 정본 파일과 읽는 조건을 직접 연결한다.
3. 기본 동작을 바꾸면 기존 동작을 호환 모드나 명시 옵션으로 유지할지 판정한다.
4. 출력 경로와 파일명이 바뀌면 기존 경로의 읽기 fallback을 검토한다.
5. `agents/openai.yaml`의 기본 프롬프트가 실제 선택 모드와 요청 범위를 과장하지 않는지 확인한다.
6. 수정한 Markdown은 최종본만 남기고 문서 끝 `## 이력관리`의 같은 날짜 항목을 갱신한다.

## 변경 후 검증

아래 순서로 검증한다.

1. `ruby scripts/validate_ct_skills_test.rb`로 검증기 자체 회귀 테스트를 실행한다.
2. `ruby scripts/validate_ct_skills.rb`로 직접 참조 파일의 존재와 보조 리소스의 연결을 확인한다.
3. `ruby scripts/validate_ct_skills.rb --against HEAD`로 모든 2단계 계약 섹션, 직접 연결된 `references/`, `templates/`, `workflow/`, `components/` 문서의 추가·삭제·본문 변경, `agents/openai.yaml` 표시 정보·호출 정책의 변경을 확인한다.
   - 일반 설명 문서의 fenced code 예시는 계약 비교에서 제외한다.
   - `templates/` 아래 Markdown과 `SKILL.md`가 템플릿 정본으로 직접 연결한 문서는 fenced code까지 계약으로 비교한다.
   - 계약 변경이 있으면 실패해야 하는 자동화에서는 `ruby scripts/validate_ct_skills.rb --against HEAD --fail-on-contract-change`를 사용한다.
4. Git 반영 준비 후 `ruby scripts/validate_ct_skills.rb --tracked`로 신규 reference, template, script와 asset의 추적 여부를 확인한다.
5. `git diff --check -- skills/ct-*`를 실행한다.
6. `CONTRACT_CHANGE`로 보고된 변경이 요청 범위와 호환 정책에 맞는지 대조한다.
7. 대표 명시 호출과 자연어 호출로 트리거 범위를 확인한다.
8. 대표 입력으로 출력 경로, 필수 섹션, 완료 조건과 fallback을 확인한다.
9. 저장소의 기존 검증 도구를 우선 사용하고, 검증 전용 임시 스크립트나 패키지 설치 없이 대체 가능한 기본 검사를 수행한다.
10. 의존성 부족으로 실행하지 못한 검증은 원인, 대체 검증 범위, 남은 확인 항목을 기록한다.

## 대표 호출 시나리오

스킬의 실제 진입 방식과 기본 계약이 함께 유지되는지 확인한다.

| 시나리오 | 대표 호출 | 확인 기준 |
|---|---|---|
| 명시 호출 | `$ct-{skill} ...` | frontmatter의 명시 트리거와 기본 실행 절차가 연결된다. |
| 일반 업무 요청 | `$ct-*` 없이 기능만 요청 | CT 스킬을 호출하지 않는다. |
| CT 초안 요청 | `$ct-create-skills 감사 스킬 초안` | `초안` 요청이므로 대화 초안만 만든다. |
| 명시적 파일 반영 | `$ct-create-skills ... skills/audit-skill에 파일로 생성해줘` | 지정한 경로와 확정된 파일만 생성·수정한다. |
| 기존 결과 호환 | 기본 출력 경로 밖에 legacy 문서가 있는 요청 | 정해진 탐색 순서로 기존 문서를 갱신하고 중복 생성을 막는다. |
| 조건부 모드 | 호환 모드나 선택 옵션을 명시한 요청 | 기본 모드와 조건부 산출물의 경계가 유지된다. |
| 조건부 완료 게이트 | 고위험, 외부 연동, 단계적 출시 또는 정책 판정 요청 | 해당 조건의 추가 산출물과 완료 기준만 적용한다. |
| 입력 누락 | 필수 진입점·대상·목적이 빠진 요청 | 추측하지 않고 스킬에 정의된 최소 질문만 한다. |

각 시나리오는 대화 결과뿐 아니라 생성 경로, 변경 파일, 최종 보고 항목까지 대조한다.

## 완료 기준

- 기존 기능이 유지되거나 변경 이유와 호환 경로가 명시됐다.
- 각 상세 규칙의 정본이 하나로 확정됐다.
- 모든 직접 참조 파일이 존재한다.
- `references/`, `templates/`, `workflow/`, `components/`의 보조 문서가 `SKILL.md`의 정확한 경로나 동적 선택 경로로 연결됐다.
- 직접 연결된 보조 문서의 추가·삭제·본문 변경과 템플릿 정본의 fenced code 변경이 `CONTRACT_CHANGE`에 포함됐다.
- UI 메타데이터와 실제 동작이 일치한다.
- 구조 검증과 대표 호출 검증 결과가 기록됐다.
