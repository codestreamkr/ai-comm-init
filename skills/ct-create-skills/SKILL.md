# CT Create Skills

## 목적

이 스킬은 새 스킬을 바로 만들기보다, 먼저 최소 입력을 받아 초안을 안정적으로 만드는 절차를 제공한다.

## 최우선 규칙

- 첫 응답에서는 스킬을 생성하지 않는다.
- 첫 응답에서는 아래 입력 가이드만 그대로 제공한다.
- 사용자가 `1. 스킬명`, `2. 호출명`, `3. 목적`을 주기 전에는 파일을 만들지 않는다.
- 스킬명은 기본 커맨드 이름으로 사용한다.
- 호출명은 추가 별칭이자 자연어 트리거로 사용한다.
- 모든 스킬은 기본적으로 `$스킬명`과 `호출명`을 함께 설명한다.
- 디스플레이명은 별도 입력으로 받지 않고 항상 스킬명과 동일하게 쓴다.
- 입력이 3개 다 들어오면 나머지는 목적 문장에서 최대한 유추한다.
- 유추가 어려우면 질문은 하나만 짧게 한다.

## 첫 응답 형식

첫 응답은 반드시 아래 형식을 그대로 사용한다.

```text
스킬을 바로 만들지 않고 먼저 초안 생성에 필요한 최소 정보만 받습니다.
아래 형식으로 답해 주세요.

1. 스킬명:
2. 호출명:
3. 목적:

예시
1. 스킬명: external-architect
2. 호출명: 호페형
3. 목적: 외부 연동 구조를 절차적으로 분석하고 설계 문서를 만든다.
```

## 입력을 받았을 때 할 일

### 1. 입력 확인

아래 세 항목이 모두 있는지 확인한다.

- 스킬명
- 호출명
- 목적

디스플레이명은 따로 받지 않는다.
생성 시 `agents/openai.yaml`의 `display_name`에는 스킬명을 그대로 넣는다.
트리거는 기본적으로 `$스킬명`과 `호출명`을 사용한다.
필요하면 스킬 설명에 `호출명 도와줘` 같은 자연어 예시를 함께 적는다.

하나라도 빠지면 누락 항목만 짧게 알려주고 다시 받는다.

### 2. 목적 문장 기반 추론

호출명과 목적 문장을 보고 아래를 유추한다.

- 스킬 성격: 분석, 설계, 구현, 리뷰, 문서, 위임
- 작업 흐름: 체크리스트 우선, 절차 고정, 탐색 후 제안, 바로 구현
- 보조 파일 필요 여부: `agents/`, `workflow/`, `vendors/`, `references/`
- 최종 산출물 성격: 문서, 구현 가이드, 리뷰 리포트, 실행 절차
- 자연어 호출 방식: `호출명`, `호출명 도와줘`, 문맥 호출 중 무엇을 본문에 적을지

### 3. 기본 추론 규칙

- `분석`, `설계`, `구조`, `이관`, `전환`이 있으면 분석/설계형으로 본다.
- `절차`, `순서`, `단계`, `체크리스트`가 있으면 `workflow/`를 만든다.
- `위임`, `조수`, `병렬`, `통합`이 있으면 `agents/`를 만든다.
- `결제`, `인증`, `웹훅`, `벤더`, `외부 연동`이 있으면 `vendors/` 후보를 검토한다.
- `리뷰`, `감사`, `점검`이 있으면 리뷰형 출력 구조를 우선한다.
- `문서`, `가이드`, `정리`가 있으면 최종 산출물을 문서형으로 본다.

### 4. 추가 질문 기준

아래처럼 초안 구조가 크게 달라지는 경우에만 질문을 한 번 한다.

- `workflow/`를 만들지 말지 판단이 안 되는 경우
- `agents/`가 필요한지 판단이 안 되는 경우
- 벤더 분기 파일이 필요한지 판단이 안 되는 경우

질문은 한 번에 하나만 한다.

## 초안 생성 범위

기본 생성 파일은 아래 둘이다.

- `SKILL.md`
- `agents/openai.yaml`

`agents/openai.yaml`을 만들 때는 아래를 기본값으로 사용한다.

- `display_name`: 스킬명과 동일
- `default_prompt`: `$스킬명` 호출을 우선 예시로 반영
- `when_to_use`: `$스킬명`, `호출명` 기준으로 짧게 정리

추론 결과에 따라 아래를 추가한다.

- `workflow/*.md`
- `agents/agent-*.md`
- `vendors/*`
- `references/*`

## 출력 형식

초안을 생성할 때는 아래 순서로 정리한다.

1. 입력 요약
2. 자동 판단 결과
3. 생성할 파일 구조
4. `SKILL.md` 초안
5. `agents/openai.yaml` 초안
6. 추가 파일 초안
7. 확인 필요 항목

## 문서 작성 원칙

- 사용자가 바로 복붙할 수 있는 초안을 만든다.
- 설명보다 실제 스킬 본문 초안을 우선한다.
- 불필요한 보조 문서는 만들지 않는다.
- 템플릿 설명을 길게 쓰기보다, 스킬이 바로 동작할 수 있는 구조를 제시한다.
- 기존 스킬 패턴을 참고하더라도, 목적에 맞지 않는 폴더는 억지로 만들지 않는다.
- 디스플레이명은 항상 스킬명과 같게 유지한다.
- 트리거는 `$스킬명`과 `호출명`을 기본으로 설명한다.
- 호출 예시는 커맨드형과 자연어형을 함께 적는다.

## 금지

- 첫 응답에서 바로 스킬 파일을 만들지 않는다.
- 사용자 입력이 부족한데 임의로 스킬 이름을 확정하지 않는다.
- 호출명을 스킬명과 자동으로 같다고 확정하지 않는다.
- 목적 문장과 무관한 복잡한 폴더 구조를 과하게 만들지 않는다.
- 확인이 필요한 사항이 있는데도 긴 질문 목록을 던지지 않는다.
