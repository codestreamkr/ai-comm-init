# ADR 형식

## 파일

- 위치: `.debrief/decisions/NNNN-<제목>.md`
- 번호: `decisions/`와 `decisions/archive/`의 가장 큰 번호에 1을 더한다. 4자리로 쓴다.
- 제목: 결정을 짧은 명사구로 쓴다. 공백은 `-`로 바꾼다. 예: `0007-환불-우선-처리.md`

## 본문

```markdown
# 0007. 환불을 재고 복원보다 먼저 처리

- 날짜: 2026-10-18
- 상태: 채택
- 도메인: order
- 관련 실행: plan-1, apply-1
- 영향 문서: .docs/order/order-domain.md

## 맥락

- 주문 취소 시 환불과 재고 복원을 함께 처리한다.
- 두 처리의 순서에 따라 실패 시 되돌릴 범위가 달라진다.

## 결정

- 환불을 먼저 처리한다. 환불이 성공한 뒤 재고를 복원한다.

## 이유

> 환불이 실패하면 재고를 되돌릴 필요가 없어서 단순하다.

## 버린 대안

- 재고 복원 우선: 환불 실패 시 재고를 다시 차감해야 한다.
```

| 항목 | 작성 주체 | 규칙 |
|---|---|---|
| 상태 | `ct-debrief` | `채택`, `대체됨`, `폐기` 중 하나 |
| 도메인 | `ct-debrief` | 저장소의 도메인 이름. `README.md` 분류 기준이다. |
| 관련 실행 | `ct-debrief` | 맵 이벤트의 `run` 값 |
| 영향 문서 | `ct-debrief` | 이 결정이 반영되어야 할 최종 문서. 없으면 `없음` |
| 맥락, 결정 | AI | 변경 내용과 계획에서 쓴다. 확인한 사실만 쓴다. |
| 이유 | 사용자 | 사용자가 고른 보기 문구 또는 직접 쓴 답변을 인용으로 쓴다. 고쳐 쓰지 않는다. |
| 버린 대안 | AI | 계획에서 비교한 선택지만 쓴다. 없으면 항목을 지운다. |

## 변경 규칙

- 작성한 ADR의 본문은 수정하지 않는다.
- 결정을 바꾸면 새 ADR을 만든다. 기존 ADR은 상태만 `대체됨`으로 바꾸고 `- 대체: NNNN` 줄을 추가한다.
- `대체됨`과 `폐기` ADR은 `decisions/archive/`로 옮긴다.

## 목록 (`decisions/README.md`)

- 유효한 `채택` ADR만 도메인별로 쓴다.

```markdown
# 유효 ADR

## order

- [0007. 환불을 재고 복원보다 먼저 처리](0007-환불-우선-처리.md)
```
