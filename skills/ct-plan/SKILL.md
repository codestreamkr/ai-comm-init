# CT Plan

사용자 목표와 프로젝트 근거로 문제를 탐색한다. 실행할 수 있는 계획을 정리한다.

- 계획 문서 외의 파일과 외부 상태는 변경하지 않는다.
- 구현과 검증은 실행하지 않는다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력, 예제만 안내한다.
- 탐색 요청에는 근거, 선택지, 미결정 사항을 대화로 정리한다.
- 계획 요청에는 기존 계획과 자료를 확인한다. 그다음 계획을 쓰거나 갱신한다.

예: `$ct-plan 주문 취소 기능의 구현 계획을 작성해줘`

## 수행

- 요청과 프로젝트를 조사한다. 확인한 사실, 해석, 미확인 사항을 구분한다.
- 선택지마다 영향과 근거를 제시한다.
- 계획에 다음 항목을 쓴다: 목표, 범위, 제외 범위
- 각 요구사항을 완료 조건, 작업 순서, 검증 방법에 연결한다.
- 필요하면 전환, 중단, 복구 조건도 쓴다.
- 계획 순서대로 전체 흐름을 검토한다. 흐름은 시작에서 구현, 검증, 완료 보고까지이다.
  - 각 단계의 입력, 선행 작업, 도구, 권한이 준비되어 있는지 확인한다.
  - 준비되지 않은 항목은 앞 단계에서 확보되는지 확인한다.
  - 빠진 연결과 예상 차단 지점을 계획에 반영한다.
- 계획 보고는 작업 순서에 따라 수정 영역별로 정리한다. 각 영역에 대상 파일과 작업 내용을 함께 표시한다.
- 같은 목적의 여러 파일은 한 묶음으로 나열한다. 설명은 한 번만 쓴다.
- 파일별 반복 설명보다 변경 범위와 작업 순서를 파악하기 쉬운 형식을 먼저 사용한다.
- 대상 파일은 프로젝트 조사로 확인한다.
- 아직 특정하지 못한 파일은 미확정으로 표시한다.
- 실행 단계에서 범위가 바뀌면 계획에도 반영한다.
- 실행을 막거나 결과를 바꾸는 미결정 사항은 계획 단계에서 사용자에게 확인한다.
- 실행 중에 판단할 수 있는 사항은 판단 기준과 후속 작업을 명시한다.
- 예상 실패에는 필요한 조건을 정한다: 재시도, 대안, 중단, 재개
- 계획을 변경하면 관련 요구사항, 작업, 검증 기준도 함께 맞춘다.

## 완료

- 탐색은 요청한 판단을 마치면 끝낸다.
- 계획은 다음 조건을 모두 충족하면 끝낸다. 임의의 개선 횟수로 종료하지 않는다.
  - 모든 확정 요구사항이 작업, 완료 조건, 검증 방법에 연결되었다.
  - 한 작업 턴에서 구현, 검증, 완료 보고까지 이어지는 경로를 확인했다.
  - 이 경로에 해결되지 않은 차단 요인이 없다.
- 계획은 요청한 위치에 저장한다. 위치가 없으면 프로젝트 관례를 따른다.
- 별도 파일이 필요 없는 요청에는 대화로 답한다.
- 계획 단계에서 작업을 완료로 표시하지 않는다.
- 다음 항목을 짧게 보고한다.
  - 결정 사항과 미결정 사항
  - 계획 위치
  - `ct-apply`가 시작부터 완료까지 진행할 수 있는지 여부
- 해결되지 않은 차단 요인이 있으면 계획을 실행 준비 완료로 표시하지 않는다. 필요한 입력, 결정, 권한과 재개 지점을 남긴다.
