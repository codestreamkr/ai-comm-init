# CT Plan

요청 대상의 근거를 수집해 실행 가능한 계획을 작성한다.

## 호출

- `$ct-plan` 또는 `$ct-plan ?`: 작업 목록과 대표 예제를 안내한다.
- `$ct-plan <작업> ?`: 해당 작업의 입력, 출력, 예제를 안내한다.
- `$ct-plan <작업> <요청>`: 지정한 작업을 실행한다.
- 작업 없이 요청이 이어지면 요청 내용에 맞는 작업을 선택한다.

## 작업

- `pd`: 제품·기능의 목표, 사용자 흐름과 요구사항을 기획한다.
  - 예: `$ct-plan pd 주문 취소 기능을 기획해줘`
- `review`: 설계안의 근거, 영향, 위험과 결정 사항을 검토한다.
  - 예: `$ct-plan review .docs/payment-design.md`
- `impl`: 기능 변경 범위, 구현 순서와 검증 기준을 계획한다.
  - 예: `$ct-plan impl 쿠폰 중복 적용 방지 기능`
- `improve`: 현재 코드와 구조에서 개선 과제와 우선순위를 도출한다.
  - 예: `$ct-plan improve 회원 모듈`

## 자료 수집

요청과 관련된 자료만 확인한다.

- 적용되는 프로젝트 규칙 문서
- 사용자 요구사항과 지정 문서
- 프로젝트 구조, 빌드, 설정과 관련 코드
- 기존 설계, 테스트와 운영 제약
- 같은 역할을 하는 기존 산출물

프로젝트 밖의 제품 기획은 사용자가 제공한 자료와 확인된 외부 근거를 기준으로 한다.

## 실행

1. 요청의 목적, 대상과 산출물을 확정한다.
2. 판단에 필요한 프로젝트 및 사용자 자료를 수집한다.
3. 현재 상태, 목표, 영향과 검증 기준을 연결한다.
4. 선택한 작업에 맞는 계획을 작성한다.

## 작업별 출력

- `pd`: 목표, 대상 사용자, 요구사항, 사용자 흐름, 성공 기준
- `review`: 검토 근거, 발견 사항, 대안, 결정 필요 항목
- `impl`: 변경 대상, 영향 범위, 구현 순서, 검증 기준
- `improve`: 현황 근거, 개선 과제, 우선순위, 기대 효과

저장 위치와 문서 형식은 사용자 지정 또는 프로젝트의 기존 패턴을 따른다.

## 완료 조건

- 계획의 주요 판단이 확인된 근거와 연결된다.
- 범위, 결과물과 검증 기준이 분명하다.
- 미확인 사항이 확정된 내용과 구분된다.
