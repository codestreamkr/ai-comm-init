# CT Plan

사용자 목표와 프로젝트 근거로 문제를 탐색하고 실행 가능한 계획을 정리한다. 계획 문서 외의 파일과 외부 상태는 변경하지 않으며 구현·검증을 실행하지 않는다.

## 호출

- 요청 없이 호출하면 역할, 필요한 입력과 예제만 안내한다.
- 탐색 요청은 근거·선택지·미결정 사항을 대화로 정리한다. 계획 요청은 기존 계획과 자료를 확인해 계획을 작성하거나 갱신한다.

예: `$ct-plan 주문 취소 기능의 구현 계획을 작성해줘`

## 수행

- 요청과 프로젝트를 조사해 확인한 사실, 해석, 미확인 사항을 구분하고 선택지의 영향과 근거를 제시한다.
- 계획에는 목표·범위·제외 범위와 각 요구사항의 완료 조건·작업 순서·검증 방법을 연결한다. 필요한 전환·중단·복구 조건도 포함한다.
- 계획 순서대로 시작부터 구현·검증·완료 보고까지 흐름을 검토한다. 각 단계의 입력·선행 작업·도구·권한이 준비되어 있거나 앞 단계에서 확보되는지 확인하고, 빠진 연결과 예상 차단 지점을 계획에 반영한다.
- 계획 보고는 작업 순서에 따라 수정 영역별로 정리하고, 각 영역에 대상 파일과 작업 내용을 함께 표시한다.
- 같은 목적의 여러 파일은 한 묶음으로 나열하고 설명은 한 번만 작성한다. 파일별 반복 설명보다 변경 범위와 작업 순서를 파악하기 쉬운 형식을 우선한다.
- 대상 파일은 프로젝트 조사로 확인한다. 아직 특정하지 못한 파일은 미확정으로 표시하고, 실행 단계에서 범위가 달라지면 계획에도 반영한다.
- 실행을 막거나 결과를 바꾸는 미결정 사항은 계획 단계에서 확인받는다. 실행 중 판단 가능한 사항은 판단 기준과 후속 작업을 명시한다. 예상 실패에는 필요한 재시도·대안·중단·재개 조건을 정하고, 계획 변경 시 관련 요구사항·작업·검증 기준을 함께 맞춘다.

## 완료

- 탐색은 요청한 판단을 마칠 때 마친다. 계획은 모든 확정 요구사항이 작업·완료 조건·검증 방법에 연결되고, 해결되지 않은 차단 요인 없이 한 작업 턴에서 구현·검증·완료 보고까지 이어지는 경로가 확인될 때 마친다. 임의의 개선 횟수로 종료하지 않는다.
- 계획은 요청한 위치 또는 프로젝트 관례에 저장하고, 별도 파일이 필요 없는 요청은 대화로 답한다. 계획 단계에서 작업을 완료로 표시하지 않는다.
- 결정·미결정 사항, 계획 위치, `ct-apply`가 시작부터 완료까지 진행할 수 있는지 짧게 보고한다. 해결되지 않은 차단 요인이 있으면 계획을 실행 준비 완료로 표시하지 않고, 필요한 입력·결정·권한과 재개 지점을 남긴다.
